# IIC Tool v6 代码架构分析报告

## 一、项目概述

**IIC Tool v6** 是一个基于 Python/Tkinter 的 Windows GUI 桌面工具，用于通过 USB 转 IIC 硬件适配器与 **2361 芯片**进行 I2C 通信，实现寄存器读写和 MTP（多次可编程存储器）烧录/擦除/校验。支持通过 Excel 文件进行批量操作。

- **主入口**: `IICtool_v6/IICtool.py`
- **Python 版本**: 推荐 3.8.5
- **依赖库**: `pyserial`（串口通信）、`openpyxl`（Excel 读写）
- **打包工具**: PyInstaller（spec 文件: `IICtool_v6.spec`）
- **核心 DLL**: `USB2UARTSPIIICDLL.dll`（USB 转 IIC 硬件底层驱动）

### 2. `i2c_comm.py` — I2C 通信层 (744行)

**类**: `I2CController`

**职责**: 封装底层硬件通信，包括串口管理、DLL（动态链接库）加载、I2C/SPI/PWM 操作。

**设计模式**: 适配器模式，将 C DLL 接口适配为 Python 方法。

**DLL 接口映射**（通过 `ctypes.WinDLL` 加载 `USB2UARTSPIIICDLL.dll`）:
| DLL 函数 | Python 方法 | 用途 |
|----------|-------------|------|
| `OpenUsb` / `CloseUsb` | `_ensure_dll_ready()` / `close()` | USB 设备生命周期 |
| `ConfigIICParam` | `_ensure_dll_ready()` / `set_iic_speed()` | IIC 参数配置（速率等） |
| `IICSendData` | `_dll_i2c_send()` / `send_custom_write_frame()` | I2C 数据发送 |
| `IICRcvData` | `_dll_i2c_recv()` | I2C 数据接收 |
| `IICSendAndRcvData` | `_dll_i2c_send_and_recv()` | I2C 发收一体 |
| `PWMOut` / `PWMClose` | `pwm_start()` / `pwm_close()` | PWM 脉冲输出（触发 SCK） |
| `IOSetAndRead` | `io_set_and_read()` | IO 设置与读取 |
| `ConfigureSPIParam` / `SPISendData` / `SPIRcvData` | SPI 相关方法 | SPI 模式支持 |
| `InternalList*` | `spi_send_sck_internal()` | 内部列表模式脉冲发送 |

**核心协议方法**:
| 方法 | 功能 |
|------|------|
| `init_i2c()` | 通过串口发送 I2C 初始化命令 `03000808...` |
| `send_custom_write_frame()` | 发送自定义写帧（全8位直发） |
| `read_stop_then_start()` | 2361读协议：两阶段——先发读命令STOP，再START发A5读地址帧，收4字节ACK后STOP |
| `_dll_i2c_two_start_read_ack_stop_immediate()` | 连续ACK+立即STOP读时序 |
| `recover_bus_manual()` | 手动总线恢复（重新OpenUsb+ConfigIICParam） |
| `set_iic_speed()` | 设置 IIC 速率（1k~400k 共9档） |

**关键属性**:
- `read_timeout_ms = 20` — 读取超时时间
- `pwm_base_clock = 48000000` — PWM 基准时钟 48MHz
- `slave_addr = 0x52` — I2C 从机地址（7位）

### 3. `iic_ops.py` — IIC 操作与业务逻辑层 (507行)

**包含**: 模块级函数 + `IICLogic` 类

#### 模块级核心函数

| 函数 | 功能 |
|------|------|
| `_reverse_bits(x, width)` / `_reverse_bits_32(x)` | 位反转（2361协议要求） |
| `build_iic_payload(rw, addr, index, write_data)` | 构建2361报文（RW码+5位ADDR反序+6位INDEX反序+4字节数据32位反序） |
| `execute_write(i2c_ctrl, addr, index, write_data, log_cb)` | 执行2361写操作（前缀0x25） |
| `execute_read(i2c_ctrl, addr, index, log_cb)` | 执行2361读操作（两阶段：0x25发读命令STOP + 0xA5发读地址帧收4字节） |

#### `IICLogic` 类（全静态方法）

| 方法 | 功能 |
|------|------|
| `parse_hex_bytes(s)` | 解析多字节HEX字符串 |
| `parse_hex_exact4(s)` | 解析精确4字节HEX（支持补零） |
| `parse_hex_byte(s, col_name)` | 解析单字节HEX值 |
| `parse_number_list_or_range(text, min, max, name)` | 解析数字列表/范围（如 "0-10,15,20"） |
| `generate_template(filename)` | 生成 IIC 批量操作 Excel 模板 |
| `read_data_and_export_template(...)` | 按地址/索引范围批量读取并导出 Excel |
| `import_and_execute_batch(filename, write_cb, read_cb, log_cb)` | 解析 Excel 并执行批量写→读→校验（支持 START/END 标记、#注释） |
| `import_and_update_reads(filename, ..., progress_cb)` | 逐行读回寄存器值并覆盖 Excel |

**2361 协议报文结构**:
```
写操作: [0x25] [报头高字节] [报头低字节] [数据字节0] [数据字节1] [数据字节2] [数据字节3]
读操作: 阶段1→ [0x25] [报头高字节] [报头低字节] + STOP
        阶段2→ START + [0xA5] + 接收4字节 + ACK + STOP

报头(16位): [RW(3bit)] [ADDR_rev(5bit)] [INDEX_rev(6bit)] [00(2bit)]
RW: read=0b110, write=0b010
ADDR_rev: 5位 bit-reversal
INDEX_rev: 6位 bit-reversal
数据: 32位 bit-reversal 后发送
```

### 4. `mtp_ops.py` — MTP 操作控制器 (96行)

**类**: `MTPController`

**职责**: 封装 MTP 存储器的底层操作逻辑，通过 I2C 寄存器写入来实现 MTP 控制。

| 方法 | MTP 功能 | 底层实现 |
|------|----------|----------|
| `open_mtp_en()` | 开启 MTP 使能 | 3次I2C写: addr=25 idx=4 + addr=20 idx=15 + addr=30 idx=0, 均写入`5A5A5A5A` |
| `close_mtp_en()` | 关闭 MTP 使能 | 2次I2C写: addr=30 idx=0 + addr=20 idx=15, 均写入`A5A500A5` |
| `program_byte(addr, byte)` | 烧录单字节 | 将地址映射为 (base_addr, index)，写入 `0x400 | byte_val`，重复2次 |
| `read_byte(addr)` | 读取单字节 | 先写触发值`0x200`，再读回4字节，取最低字节 |
| `erase_sector(sector)` | 扇区擦除 | 写入 `0x800` |
| `erase_chip()` | 全片擦除 | 写入 `0x1000` |

**地址映射**: MTP 字节地址 → (ADDR, INDEX) 寄存器地址
```python
addr = (mtp_byte_addr >> 6) & 0x1F   # 高5位 → ADDR (0~31)
index = mtp_byte_addr & 0x3F          # 低6位 → INDEX (0~63)
```

**MTP 命令码**:
| 操作 | 写入值 | 含义 |
|------|--------|------|
| 读触发 | `0x200` | 触发 MTP 读 |
| 烧录 | `0x400` | byte_val | 触发 MTP 写 |
| 扇区擦除 | `0x800` | 擦除当前扇区 |
| 全片擦除 | `0x1000` | 擦除全部 MTP |

### 5. `mtp_batch_ops.py` — MTP 批量操作逻辑 (553行)

**类**: `MTPBatchLogic`（全静态方法）

**职责**: 所有 MTP 批量业务逻辑，包括 Excel 模板生成、全片烧录+CRC校验、扇区读写导出等。

| 方法 | 功能 |
|------|------|
| `generate_mtp_template(filename)` | 生成 MTP 批量操作 Excel 模板（含地址自动公式） |
| `mtp_full_program_with_crc_gui(filename, ...)` | 从 Excel 读取 PROGRAM 行，构建512字节buffer，计算CRC32并填充到 507~510 |
| `execute_mtp_burn(mtp_ctrl, buffer, phys_addrs, log_cb, progress_cb)` | 执行两遍全片烧录（含CRC区域） |
| `verify_mtp_burn(mtp_ctrl, buffer, phys_addrs, log_cb, progress_cb)` | 逐字节读回校验，返回不一致地址列表 |
| `import_and_execute_mtp_batch(filename, mtp_ctrl, log_cb, progress_cb)` | 导入 Excel 执行批量 MTP 操作（READ/PROGRAM/ERASE_SECTOR） |
| `write_mtp_sector_data(mtp_ctrl, sector, byte_val, log_cb)` | 向指定扇区32字节统一烧录 |
| `read_and_export_mtp_sector(mtp_ctrl, sector, filename, log_cb)` | 读扇区32字节并导出 Excel |
| `read_mtp_and_export_template(mtp_ctrl, filename, log_cb, progress_cb)` | 读取MTP地址4~315+CRC区域，导出为模板格式Excel |
| `mtp_full_program_with_crc(...)` | （已弃用的旧版流程，含ERASE/WRITE/READ状态机） |

**全片烧录+校验流程**:
```
1. CRC计算: 读取Excel → 构建512字节buffer → 计算地址范围CRC32 → 填充到507~510
2. 用户确认: 弹窗显示CRC值，确认已擦除+Open MTP EN
3. 烧录: 两遍逐字节 program_byte（含数据区+CRC区）
4. 校验: 逐字节 read_byte 比对，记录不一致项
5. 结果: 弹窗报告通过/失败详情
```

## 四、数据流与调用关系

```
用户操作 → GUI (IICtool.py) → 业务逻辑层 → 通信层 → DLL/硬件
                                    │
               ┌────────────────────┼────────────────────┐
               ▼                    ▼                    ▼
         iic_ops.py            mtp_ops.py          mtp_batch_ops.py
       (寄存器读写)          (MTP单步操作)        (MTP批量操作)
               │                    │                    │
               └────────────────────┼────────────────────┘
                                    ▼
                            i2c_comm.py
                          (I2CController)
                                    │
                         ┌──────────┼──────────┐
                         ▼          ▼          ▼
                     串口通信    DLL调用    PWM/IO
                    (pyserial) (ctypes)   (DLL)
```

**典型调用链示例**:
1. **IIC 寄存器读**: `I2CGUI.do_fixed_read()` → `execute_read()` → `I2CController.read_stop_then_start()` → DLL `IICSendData` + `IICSendAndRcvData`
2. **MTP 单字节烧录**: `I2CGUI.do_mtp_program_byte()` → `MTPController.program_byte()` → `I2CGUI._do_write()` → `execute_write()` → `I2CController.send_custom_write_frame()` → DLL `IICSendData`
3. **MTP 全片烧录+校验**: `I2CGUI.mtp_full_program_with_crc()` → `MTPBatchLogic.mtp_full_program_with_crc_gui()` → `MTPBatchLogic.execute_mtp_burn()` / `verify_mtp_burn()` → `MTPController.program_byte()` / `read_byte()`

## 七、架构特点总结

1. **分层清晰**: GUI层(`IICtool.py`) → 业务逻辑层(`iic_ops.py`/`mtp_ops.py`/`mtp_batch_ops.py`) → 通信层(`i2c_comm.py`) → 硬件DLL
2. **静态方法解耦**: `IICLogic` 和 `MTPBatchLogic` 采用全静态方法设计，通过回调函数（`log_cb`、`progress_cb`、`execute_*_cb`）与 GUI 和硬件层解耦
3. **两套并行GUI代码**: `gui_iic.py`/`gui_mtp.py` 实现了与 `IICtool.py` 中内嵌 GUI 构建代码功能相同的分离式版本，但当前未被主程序引用（可能是重构过程中的过渡产物）
4. **2361芯片专用协议**: 核心读写使用位反转（bit-reversal）编码，写操作前缀`0x25`，读操作为两阶段`0x25`+STOP+`0xA5`
5. **MTP通过寄存器间接操作**: MTP 的读写擦除不是直接内存访问，而是通过 I2C 寄存器写入特定的命令码（0x200/0x400/0x800/0x1000）来触发
6. **错误恢复机制**: 读超时自动触发总线恢复（重新 OpenUsb + ConfigIICParam），支持手动"主动拉高/恢复死锁"
7. **批量操作支持完备**: 支持 Excel 模板生成→填写→批量执行→校验的完整工作流，支持注释行、START/END 标记
