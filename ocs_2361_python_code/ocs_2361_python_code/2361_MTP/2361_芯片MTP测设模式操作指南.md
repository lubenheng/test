# 2361 芯片 MTP操作测试指南

本文档阐述了进入 2361 芯片测试模式后，针对内部 MTP（多次可编程存储器）的读、写（烧录）、擦除操作流程，以及数据通信期间使用的 CRC-32 校验规范。

## 一、 I2C 接口总线协议基本规范
*   **传输规则**：每帧包含 `8bit 数据 + 1bit ACK`。低字节（LSB）先发送，而在单个字节内数据位是高位（MSB）先发（标准的 I2C 位序）。
*   **接口字段定义**：
    *   `slv_addr`：5bit 从机地址（对应 I2C 7bit 地址的高 5 位，低 2 位为读写控制位或预留）。
    *   `reg_addr`：11bit 寄存器或存储地址。
    *   `wdata`：32bit 写入数据（分 4 个字节，低字节 LSB 先发送）。
    *   `rdat`：32bit 读出数据（分 4 个字节，低字节 LSB 先发送）。
*   **整体 MTP 操作生命周期**：开启手动使能 → [批量读/写/擦除] → 关闭手动使能。

---

## 二、 MTP 存储区扇区划分 (Sector Map)
MTP 存储区域被划分为 16 个扇区（Sector），每个扇区大小为 **32 bytes**。最大支持 `16 * 32 = 512 bytes`，各扇区地址范围划分如下：

| 扇区编号 (Sector) | 地址范围 (bytes) | 备注 |
| :--- | :--- | :--- |
| **0** | **4 - 31 byte** | 注意：首地址从 4 开始 |
| 1 | 32 - 63 byte | |
| 2 | 64 - 95 byte | |
| 3 | 96 - 127 byte | |
| ... | ... | (每个递增 32 bytes) |
| 14 | 448 - 479 byte | |
| 15 | 480 - 511 byte | 最后一个扇区 |

> ⚠️ **前 4 bytes (0-3 byte)** 的用途特殊，未在此普通可擦除扇区列表中，请结合具体芯片手册进行操作。

---

## 三、 权限控制 (手动使能)
对 MTP 进行任何（读/写/擦）操作前，**必须先开启 MTP 操作使能 (open mtp en)**。操作完全结束后，**必须关闭使能 (close mtp en)**。

*   **开启使能 (Open MTP EN)**
    *   步骤：对内部 `apb_wdat[8]` 位写 1。
    *   操作：写地址 `11110_000000`，写入数据 `1_0000_0000`（十六进制：`32'h100`）。
*   **关闭使能 (Close MTP EN)**
    *   步骤：对内部 `apb_wdat[8]` 位写 0。
    *   操作：写地址 `11110_000000`，写入数据 `0_0000_0000`。

---

## 四、 MTP 读操作流程
读操作需要向目标地址写入特定的读命令（产生读脉冲），随后从总线上把对应地址的数据回读出来。

| 步骤 | 操作类型 | 目标地址 | 写入数据/动作 | 功能说明 |
| :--- | :---: | :--- | :--- | :--- |
| 1 | 写 | `11110_000000` | `1_0000_0000` | 开启 MTP 使能 (`open mtp en`) |
| 2 | 写 | `00000_000101` | `10_0000_0000` | 向地址 5 发送读脉冲（令 `apb_wdat[9]=1`，产生 `rd_trig`） |
| 3 | 读 | `00000_000101` | 读取至 `rdat` | 硬件将 MTP 数据放至总线，通过 i2c 读回第 5 Byte 的数据 |
| 4 | 写 | `00000_000110` | `10_0000_0000` | 向地址 6 发送读脉冲（触发读取操作） |
| 5 | 读 | `00000_000110` | 读取至 `rdat` | 通过 i2c 读回第 6 Byte 的数据 |
| 6 | 写 | `11110_000000` | `0_0000_0000` | 读取结束，关闭 MTP 使能 (`close mtp en`) |

---

## 五、 MTP 擦除操作 (Erase)
进行烧录之前，**必须先确保目标区域已被擦除**。系统支持“全片擦除 (Chip Erase)”和“按扇区擦除 (Sector Erase)”。

### 1. 全片擦除 (Chip Erase)
| 步骤 | 操作类型 | 目标地址 | 写入数据 | 功能说明 |
| :--- | :---: | :--- | :--- | :--- |
| 1 | 写 | `11110_000000` | `1_0000_0000` | 开启 MTP 使能 |
| 2 | 写 | `10000_000000` | `1_0000_0000_0000` | 触发全片擦除（对 `apb_wdat[12]` 写 1 产生片擦除脉冲）。*注：开启使能后全局擦除对应的地址位可任意，该地址仅供参考。* |
| 3 | 等待 | - | - | **强制等待 300 ms**，直到硬件完成全片擦除。 |
| 4 | 写 | `11110_000000` | `0_0000_0000` | 擦除结束，关闭 MTP 使能 |

### 2. 扇区擦除 (Sector Erase)
| 步骤 | 操作类型 | 目标地址 | 写入数据 | 功能说明 |
| :--- | :---: | :--- | :--- | :--- |
| 1 | 写 | `11110_000000` | `1_0000_0000` | 开启 MTP 使能 |
| 2 | 写 | `00_<Sector>_00000` | `1000_0000_0000` | 触发扇区擦除（对 `apb_wdat[11]` 写 1 产生扇区擦除脉冲）。`<Sector>` 为 4bit 的扇区号（0至15）。 |
| 3 | 等待 | - | - | 等待固定时间（等待硬件完成擦除）。 |
| 4 | 写 | `11110_000000` | `0_0000_0000` | 擦除结束，关闭 MTP 使能 |

> **地址计算示例**：由于每个扇区 32 字节，取地址的高位（忽略低 5 位的偏移），`mtp_addr[8:5]` 正好对应 0~15 号扇区。例如擦除第 1 扇区时，目标地址的高位包含 `0001`。

## 六、 MTP 烧录操作 (Program)
> ⚠️ **注意：烧录前请务必确认目标扇区或整个芯片已执行过擦除操作！**

| 步骤 | 操作类型 | 目标地址 | 写入数据 | 功能说明 |
| :--- | :---: | :--- | :--- | :--- |
| 1 | 写 | `11110_000000` | `1_0000_0000` | 开启 MTP 使能 |
| 2 | 写 | `<MTP Target Addr>` | `{1'b1, 2'b00, reg[7:0]}` | 向 `apb_wdat[10]` 写 1 产生烧录脉冲，同时将要烧录的数据写到 `apb_wdat[7:0]` 中。 |
| 3 | 等待 | - | - | 等待固定时间让硬件将 1 个 Byte 数据写入介质中。 |
| 4 | 写 | `<MTP Target Addr + 1>` | 类似步骤 2 的格式 | 烧录下一个 Byte。 |
| ... | ... | ... | ... | 循环批量烧录完成。 |
| N | 写 | `11110_000000` | `0_0000_0000` | 烧录结束，关闭 MTP 使能 |

## 七、 异常处理与 CRC 校验
系统为防止 MTP 数据在写入或由于老化过程中产生错误，需要在特定位置校验数据完整性。将 MTP 中 `地址 4` 开始到 `地址 315` 的数据，逐字节进行 CRC-32 计算。计算得出的校验值需存储在使用规范指定的 MTP 尾部区域（例如地址 507 ~ 510）。

### 1. 寄存器对应 MTP 数据地址与 CRC 校验区域说明
根据设计规范，Digital 侧需要烧录至 MTP 的外设有：`adc_ctrl`、`motor`、`driver`、`foc`、`timer4`、`ana_ctrl` 等模块。
其中，每个外设的 32-bit 寄存器在烧录到 MTP 时会被拆分为四个独立的 bytes。

**CRC-32 校验的重要约束：**
* **校验范围**：CRC 校验**只校验能够烧录至 MTP 中的实际数据**。
* **校验值存储**：将外界手动计算出来的 32-bit CRC 校验值 `crc_value[31:0]`，**必须提前烧录至 MTP 结尾特定的四个字节地址中**。具体字节映射(Little-Endian 小端呈现)如下：
    * **地址 507**：存放 `crc_value[7:0]` (最低字节 LSB)
    * **地址 508**：存放 `crc_value[15:8]`
    * **地址 509**：存放 `crc_value[23:16]`
    * **地址 510**：存放 `crc_value[31:24]` (最高字节 MSB)

### 2. CRC-32 核心参数配置
本系统使用的是一套**“正向、无输出翻转、原始”**的 CRC32 规则：
*   **多项式 (Polynomial)**：`0x04C11DB7` (标准的 CRC32 生成多项式)。
*   **初始值 (Init Value)**：`0xFFFFFFFF`（全 1）。
*   **输入反转 (RefIn)**：否（正常的高位字节在前，不翻转）。
*   **输出反转 (RefOut)**：否（不翻转）。
*   **输出异或值 (XOR_OUT)**：`0x00000000`（输出结果不进行异或处理，直接返回当前值）。

### C 语言参考实现（以 2 个字节为例验证）

```c
#include <stdint.h>

// 通用版，输入多少字节就处理多少字节
uint32_t crc32_custom(const uint8_t *data, uint32_t len)
{
    const uint32_t POLY = 0x04C11DB7;
    uint32_t crc = 0xFFFFFFFF;  // 初始化为全 1

    for (uint32_t i = 0; i < len; i++)
    {
        // 每处理一个字节，将其左移至最高位与当前 crc 异或
        crc ^= (uint32_t)data[i] << 24;

        // 移位 8 次
        for (int j = 0; j < 8; j++)
        {
            if (crc & 0x80000000)
                crc = (crc << 1) ^ POLY;
            else
                crc <<= 1;
        }
    }
    return crc;  // 直接返回结果，不异或 0xFFFFFFFF
}
```
**自测验证：**
*   输入：`0x12, 0x34` -> 预期输出：`0x6A2D4287`
*   输入：`0x00, 0x00` -> 预期输出：`0x9E80F934`

## 八、 关键注意事项
1. **时序控制**：每个 MTP 读、写和擦除的步骤中间，**必须严格遵守所需的延时（等待固定时间或 300ms 等）**。不等待会导致数据丢失或芯片逻辑死锁。
2. **先擦后写**：在烧录数据前必须先对所在的扇区或整片进行擦除 (Erase)，MTP 技术特性决定只能将 1 变为 0（或 0 变为 1），不能直接覆盖旧数据。
3. **使能管理**：一定要成对使用 `open mtp en` 和 `close mtp en`，防止在非预期的时序或者在总线被干扰时导致不可逆的烧写错误。
