# ODS_5010 main.c 代码分析

## 1. 文件概述

`main.c` 是 **MCU 5010 SDK** 中 `ODS_5010` 项目的**主入口文件**。该项目是一个 MCU 外设测试验证平台，通过命令行（cmdline）交互的方式，对 MCU 各外设模块进行功能验证与调试。文件位于 `internal/ODS_5010/main.c`，共 457 行。

### 4.2 详细分析

#### 阶段 1：上电延时（第 361 行）
```c
delay_1us(2000);
```
等待 2ms，确保芯片上电稳定后再进行后续初始化。

#### 阶段 2：Flash 时钟使能（第 362 行）
```c
flash_clk_enable();
```
使能 Flash 控制器的工作时钟，为后续可能的 Flash 读写作准备。

#### 阶段 3：系统初始化（第 365 行）
```c
System_Init();
```
调用系统级初始化函数，通常包括：中断向量表配置、系统定时器（SysTick）初始化、必要的外设默认配置等。

#### 阶段 4：外设时钟使能（第 368-381 行）
依次使能各外设模块的时钟：
- **GPIO**：通用 I/O
- **MCPWM**：电机控制 PWM（当前重点测试模块）
- **UART**：串口通信
- **HWMATH**：硬件数学加速器（可能用于 ADC 数据处理或 CRC 计算）
- **ADC**：模数转换器（当前重点测试模块）
- **TIM13/14/15/16**：4 个基本定时器（可能为 MCPWM 或 ADC 提供时基）

#### 阶段 5：UART 初始化（第 396-423 行）
- **UART1**（PTA3/PTA4）：作为调试信息输出串口，**仅配置为发送模式**（`uart_receive_enable(false)`）
- **UART0**（PTA1/PTA2）：作为控制台交互串口（条件编译 `#ifdef UART` 保护）

UART0 初始化后，如果定义了 `CMDLINE_SUPPORT` 宏，会初始化命令行解析器，并通过 `INFO()` 宏打印 SDK 版本信息（`FW_VER`）和编译时间（`COMPILER_DATE`、`COMPILER_TIME`），以及当前的 MCU 系统时钟频率。

> **注意**：`uart0_clk_init()` 函数体为空（第 299-310 行被注释），说明 UART0 的时钟配置通过其他方式（可能是 `uart_clk_enable()`）完成。

#### 阶段 6：RRAM GPIO 旁路（第 425 行）
```c
rram_gpio_bypass();
```
此函数检查特定寄存器地址 `0x4002041c` 的值是否为 `0x00796783`：
- **如果已存在**：直接返回，打印 "rram gpio bypass success"
- **如果不存在**：通过 `flash_write()` 向 OTP Flash 地址 `0x27` 写入 `0x00796783`，然后延时 100us 后**软件复位 MCU**（向地址 `0x4002000C` 写入 `0x0000AB56`）

> **关键逻辑**：这是一个**一次性 OTP 配置**。芯片首次上电时，将 RRAM 的 GPIO 旁路配置写入 OTP，然后自动复位。复位后寄存器值已存在，直接跳过。这确保了配置是持久化的。

#### 阶段 7：模块测试入口（第 427-429 行）
```c
#ifdef CMD_MODULE_TEST
    module_test();
#endif
```
`CMD_MODULE_TEST` 在 `test.h` 中始终定义，但 `module_test()` 函数当前**为空实现**（`module_test.c` 中的函数体只有注释），且 `ENABLE_MODULE_TEST` 设为 `0`。因此这行代码在当前配置下**实际不产生任何效果**。

#### 阶段 8：中断使能（第 431 行）
```c
__enable_irq();
```
使能全局中断。在此之前，所有外设初始化已完成，但中断响应被屏蔽。使能后，MCPWM 等外设的中断回调（如 `MCPWM0_Call_Back`）才能被触发。

#### 阶段 9：主循环（第 436-456 行）
```c
while(1)
{
    cmdline_handle_polling();
    delay_1us(10);
}
```
主循环只做两件事：
1. **轮询处理命令行**：检查 UART0 接收缓冲区是否有命令输入，如果有则解析并执行对应测试函数
2. **延时 10us**：控制循环频率约为 100kHz，避免 CPU 空转占用过多功耗

> **被注释掉的代码**：主循环中曾有 GPIO 翻转测试代码（PTA/PTB/PTC 引脚电平翻转），现已全部注释，说明当前版本不再通过主循环直接控制 GPIO。

## 5. MCPWM0 中断回调分析

```c
uint16_t mcpwm0_callback_cnt = 0;
void MCPWM0_Call_Back(void)
{
    mcpwm0_callback_cnt++;
    UartView(mcpwm0_callback_cnt+1000, mcpwm0_callback_cnt+2000,
             mcpwm0_callback_cnt+3000, mcpwm0_callback_cnt+4000);
}
```

### 功能说明
- `MCPWM0_Call_Back` 是 MCPWM0 外设的**中断回调函数**
- 每次 MCPWM0 中断触发时，计数器 `mcpwm0_callback_cnt` 自增 1
- 通过 `UartView()` 函数将计数器值（加不同偏移）输出到 UART1 调试串口，用于观察中断触发频率

### 被注释的历史代码
- 第 46-89 行：直接通过 UART 数据寄存器（`DR_STR.DATA`）发送序列数据 `0x11~0xa6`，使用 `TXFULL` 状态位判断
- 第 91-111 行：使用 `TXEMPT` 状态位判断的另一版本

> 说明：之前可能调试过 UART 寄存器级别的直接发送，现已改用封装的 `UartView()` 函数。

## 8. 关键发现与总结

### 8.1 当前项目定位
ODS_5010 是一个**外设测试验证平台**，而非最终产品固件。它通过串口命令行与上位机/测试人员交互，动态执行各外设模块的功能测试。

### 8.2 当前激活的外设
| 外设 | 用途 | 状态 |
|------|------|------|
| **MCPWM** | 电机控制 PWM 测试 | ✅ 启用 |
| **ADC** | 模数转换测试 | ✅ 启用 |
| UART0 | 控制台命令交互 | ✅ 初始化 |
| UART1 | 调试信息输出 | ✅ 初始化 |
| TIM13/14/15/16 | 定时器（可能为 MCPWM/ADC 服务）| ✅ 时钟使能 |
| HWMATH | 硬件数学加速器 | ✅ 时钟使能 |

### 8.3 代码特点
1. **大量注释代码**：许多 GPIO 初始化和 UART 寄存器级操作代码被保留但注释，说明项目处于活跃开发/调试阶段
2. **模块化设计**：通过 `test.h` 的宏开关灵活控制各测试模块的编译
3. **OTP 自配置**：`rram_gpio_bypass()` 实现了首次上电自动写入 OTP 并复位的机制
4. **命令行驱动**：主循环仅处理命令行轮询，所有测试功能通过串口命令触发
5. **双串口架构**：UART0 用于命令交互，UART1 用于调试数据输出

### 8.4 代码中存在的问题/隐患
1. **uart0_clk_init() 为空函数**：UART0 时钟初始化逻辑缺失，依赖其他路径完成时钟配置
2. **group1_gpio_init() 未被调用**：PTC6-PTC9 的 GPIO 配置代码存在但未执行
3. **module_test() 为空实现**：虽然 `CMD_MODULE_TEST` 始终定义，但实际测试函数为空
4. **MCPWM0_Call_Back 中每中断都调用 UartView()**：如果 MCPWM 中断频率很高，可能导致 UART 发送拥塞
5. **`global_t` 结构体中声明的 `ADC_TestFlag`**（第 356 行 `u8 ADC_TestFlag;`）：该全局变量在 main.c 中定义但在 main() 中未被使用，可能在其他测试文件中被引用

## A.3 test.c —— module_test() 主入口分析

`test.c`（614 行）是整个测试系统的**核心调度器**，包含唯一的 `module_test()` 函数。该函数在 `main()` 的第 429 行被调用（`#ifdef CMD_MODULE_TEST` 保护）。

### 3.1 头文件条件包含

根据 `test.h` 中定义的宏，按需引入各模块的测试头文件：

{
    gpio_output_set(GPIO_C, GPIO_PIN_9, GPIO_HIGH_LEVEL);  // 进入标记
    mcpwm0_callback_test_cnt++;

    // 当前激活：FOC_Control_Process()  — 三相FOC电机控制
    // 备选：
    //   MC_DutyBuf_Set()               — BLDC调速
    //   mcpwm0_HPWM_LON_openloop_test() — BLDC开环六步换相（直接寄存器）

#### mcpwm1_callback_duty_test() —— MCPWM1 中断回调

### 4.4 核心函数

#### mcpwm_soft_init_copy()
将 MCPWM0/1 的初始寄存器值（周期、死区、比较值）保存到 `stru_mcpwm_shadow` 结构体，供后续运行时参数调整参考。

#### mcpwm_parameter_set()
命令行驱动的 PWM 参数动态设置函数：
- **参数格式**：`mcpwm_test <instance> <period(Hz)> <TH0-5> <deadtime_p> <deadtime_n>`
- **period 计算**：`(MCU_CLK/2) / period_hz`，频率过低时自动 8 分频
- **占空比计算**：`(duty * TH0 + 16384) >> 15`（0-32768 映射到 0%-100%）
- **死区时间**：`deadtime_us * EPWM_Tus`
- **写保护机制**：操作前写入 `0xDEAD` 解锁，操作后写入 `0xCAFE` 锁定

> **安全设计**：MCPWM 寄存器具有写保护，写入 `0xDEAD` 解锁，写入其他值（如 `0xCAFE`）锁定，防止误写。

### 4.5 BLDC 六步换相函数

### 5.4 常规采样测试：ADC_MCPWMTrig_Test_Init()

1. **ADC 配置**：
   - 分组模式：`ADC_MCPWM_TRG_GROUP`
   - 4 个分组通道数：{1, 3, 0, 0}

   - 触发源：MCPWM_TRIG0~TRIG3

4. **触发源选择**：
   - 软件触发模式（`ADC_SOFTTRIG_TEST`）：分组 0/1 使用 SW_TRIG

在常规测试基础上增加：

### 5.6 应用测试：单/双/三电阻采样

## A.9 测试框架总体架构

```
串口命令输入（UART0）
        │
        ▼
cmdline_handle_polling()     ← main() 主循环
        │
        ▼
cmdline_internal.c           ← 命令行解析
        │
        ├──→ mcpwm_test 命令  → mcpwm_parameter_set()
        ├──→ adc_test 命令    → adc_test_func()
        ├──→ gpio_test 命令   → gpio_test_func()
        └──→ ...              → ...
        
中断驱动层：
  MCPWM0_IRQ → g_mcpwm0_int_callback → mcpwm0_callback_duty_test()
                                        ├── FOC_Control_Process()
                                        └── UartView() 调试输出
                                        
  ADC_IRQ    → ADC_INTR_Process() / ADC_Task_CallBack_InPWM()
```

### 关键设计特点

1. **命令行交互**：所有测试功能通过串口命令触发，无需重新编译
2. **中断回调注册**：通过全局函数指针 `g_xxx_int_callback` 动态注册回调，灵活切换测试场景
3. **引脚复用保护**：批量 GPIO 操作自动跳过 SWD/RSTN 等关键引脚
4. **寄存器写保护**：MCPWM 关键寄存器使用 0xDEAD/0xCAFE 口令保护，防止误写
5. **在线参数调整**：支持运行时动态修改 PWM 周期、占空比、死区时间等参数
6. **多模式切换**：ADC 支持常规测试/中断测试/应用测试三种模式，BLDC 支持寄存器级/封装级/HALL 级三种控制方式
