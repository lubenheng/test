# ODS32M5010 CSA 电流采样 + 过流(OC)保护 实现分析

> 芯片：ODS32M5010（Cortex-M0+，最高 96MHz）
> 工程：`demo/pga_oc_demo`（Keil，`adc_demo.uvprojx`）
> 本文仅做分析与配置说明，**不修改任何代码**。
> 依据：数据手册《ODS32M501xUM 260720》（`manual_extract.txt`）与 SDK 源码。

## 一、背景与目标

1. **已完成**：CSA（Current Sense Amplifier，电流检测运放/PGA）运放功能。
   - `CSA_Init()` 已把 CSA 配置为：使能模块、固定通道 CH2、增益 ×8、LPF 滤波、偏置电压。
   - CSA 输出（`CSA_VSEN` / `CSA_VLPF`）可被 ADC 内部采样。
2. **待实现**：过流保护（OC, Over-Current）。
   - 芯片**内置硬件过流检测**（CSA 内部 OC 比较器），可**不依赖 CPU** 快速关断 MCPWM 输出。
   - 本文给出该链路的完整寄存器配置逻辑与推荐实现方案。

### 2.2 `CSA_Init()` 实际配置结果（对照寄存器）

```c
csa_gpio_init();                          // PA7~PA13 设模拟（见 §9 风险提示）
CSA_ENABLE(ENABLE);                       // MISC_CSACR0.RW_ANA_CSA_EN = 1
CSA_SET_InputCH(CSA_FIXED_INPUT_CH2);     // CSP=CSN=2 → GPIO11/GPIO12
CSA_InputCH_SWMode(CSA_FIXED_CH_MODE);    // RW_CSA_MODE = 0（固定通道）
CSA->MISC_CSACR1.RW_CSA_LPF_SEL = 1;      // bit17 =1 片外电容滤波
CSA->MISC_CSACR1.RW_CSA_LPF_GPIO = 1;     // bit16 =1 外接电容路径
CSA->MISC_CSACR1.RW_CSA_LPF       = 3;    // bit19:18 =11 → 800Hz 截止
CSA_SET_REF(CSA_REF_BUILD(CSA_REF_2V5, CSA_REF_DIV2)); // 偏置 = 2.5V/2 = 1.25V (0x0B)
CSA_SET_PGAGAIN(CSA_PGA_GAIN_X8);         // RW_CSA_GAIN=011 → ×8
```

> 注意：`RW_CSA_AMP_EN`（运放使能，bit1）与 `RW_CSA_DAC_EN`（bit11）未显式配置，
> 依赖复位默认值（MISC_CSACR0 复位值 = `0x0001_F802`，即 AMP_EN=1、DAC_EN=1、REF=0x1F）。
> 偏置点已调整为 1.25V（`CSA_REF_2V5=0x08 | CSA_REF_DIV2=0x03 → 0x0B`，对应手册 `01011=2.5/2V`），
> 与后续 OC 阈值 DAC（1.2V 量程）搭配更合理。

## 三、硬件过流保护链路（数据手册依据）

芯片内部信号流（基于手册 §MISC / §MCPWM / §ADC 描述）：

```
 采样电阻 U/V/W
     │
     ▼
CSA 运放(PGA, ×1~×64)   输入: PA7(+)/PA8(-)=CH0, PA9/PA10=CH1, PA11/PA12=CH2
     │  ├── CSA_VSEN（运放直接输出）
     │  └── CSA_VLPF（LPF 滤波后输出）
     ▼
 ADC CH0/CH1/CH2(CSA_VSEN), CH3(CSA_VLPF)      ← 软件采样用
     │
     └── OC 比较器（MISC_CSACR1 控制）
          ├ 输入: RW_CSA_OC_SEL（csp0/csp1/csp2/三路合成/vsen/vtest）
          ├ 阈值: OC_VTH（由内部 DAC 输出决定，见 §五）
          ├ 迟滞: RW_CSA_OC_HYS
          └ 输出: CSA > OC_VTH → OC=1（过流），可消抖(RW_CSA_OC_NG_EN / OC_NG)
                │
                ├─→ MISC_IR.RO_CSA_OC_LAT    锁存标志（软件查询/诊断）
                ├─→ MISC_CSACR1.IR_CSA_OC_NG 实时 Index（RO）
                ├─→ NVIC CSA 中断（向量表偏移 0x9C，当前 SDK 未挂载，见 §9）
                └─→ MCPWM FAIL0/1（FAIL0_SEL / FAIL1_SEL = 1 选择 CSA OC）
                      │
                      ▼
              MCPWM 急停: MOE→0, 通道强制输出 CH_DEF 默认电平,
              时基计数器暂停, EIF.FAILx_IF 置位, 可选 FAIL 中断通知 CPU
```

**关键手册依据：**
- `MCPWM0_FAIL012.FAIL0_SEL[9:8]`：`0 = IO MCPWM0_BKIN0`；`1 = CSA OC 输出`（FAIL1_SEL 同理）。
- `MCPWM0_FAIL012.MOE[6]`：`1` 正常输出；`0` 输出 `MCPWM0_CH_DEF` 默认值；
  **EIF.FAIL0_IF / FAIL1_IF 任一置 1 即触发 MOE=0**。
- FAIL 有效时**暂停对应时基计数器**（CNT0），并置位 EIF 错误标志。
- MCPWM 急停用于"不依赖 CPU 软件的处理快速关断 MCPWM 模块输出"（手册 §10 概述）。

> 结论：**推荐采用"CSA OC 比较器 + MCPWM FAIL"纯硬件保护**。响应时间 ≈
> OC 比较器延迟（亚 μs 级）+ 可选消抖（0.5~4μs）+ FAIL 滤波（16 个分频时钟），
> 可在**几 μs 内封锁全部 6 路 PWM 输出**，不依赖 CPU 主频与中断响应。

## 四、寄存器级配置详解

### 4.1 CSA 模块（MISC 基址 `0x4000_7800`）

#### MISC_CSACR0（`0x4000_7810`，复位 `0x0001_F802`）

| 位 | 名称 | 说明 |
|---|---|---|
| [31:24] | `RW_CSA_DAC_OUT` | DAC 输入信号（8bit），决定 OC 阈值（见 §五） |
| [22:20] | `RW_CSA_DAC_REF` | DAC 量程：000=1.2V, 001=1.5V, 010=2V, 011=2.5V, 100=3V, 101~111=VDD33 |
| [16:12] | `RW_CSA_REF` | CSA 偏置电压：`{基准}{分压}`，如 0x1F → VDD33/2 |
| [11] | `RW_CSA_DAC_EN` | DAC 使能（OC 阈值需要开） |
| [10:8] | `RW_CSA_GAIN` | 000~111：×1/×2/×4/×8/×12/×16/×32/×64 |
| [7:6] | `RW_CSA_CSN` | 反相通道：00=GPIO8, 01=GPIO10, 10=GPIO12, 11=GND |
| [5:4] | `RW_CSA_CSP` | 同相通道：00=GPIO7, 01=GPIO9, 10=GPIO11, 11=GND |
| [3:2] | `RW_CSA_MODE` | 通道模式：0=固定通道，1/2=自动差分/单端 |
| [1] | `RW_CSA_AMP_EN` | 运放使能 |
| [0] | `RW_ANA_CSA_EN` | CSA 电流采样模块使能 |

#### MISC_CSACR1（`0x4000_7814`，复位 `0x0000_4001`）—— **OC 核心寄存器**

| 位 | 名称 | 说明 |
|---|---|---|
| [31] | `IR_CSA_OC_NG`（RO） | OC 实时 Index：**CSA < OC_VTH → 0（正常）；CSA > OC_VTH → 1（过流）** |
| [19:18] | `RW_CSA_LPF` | 输出滤波截止频率：00=200Hz, 01=400Hz, 10=600Hz, 11=800Hz |
| [17] | `RW_CSA_LPF_SEL` | 0=片上电容滤波；1=片外电容滤波 |
| [16] | `RW_CSA_LPF_GPIO` | LPF 外接电容路径使能 |
| [15:14] | `RW_CSA_OC_NG` | OC 指示消抖时长：00=0.5μs, 01=1μs, 10=2μs, 11=4μs |
| [12] | `RW_CSA_OC_NG_EN` | OC 指示消抖使能 |
| [10:8] | `RW_CSA_OC_HYS` | OC 迟滞：000=0, 001=13mV, 010=24mV, 011=33mV, 100=41mV, 101=48mV, 110=54mV, 111=59mV |
| [6:4] | `RW_CSA_OC_SEL` | OC 检测信号：000=csp0, 001=csp1, 010=csp2, 011=csp1+csp2+csp3, 100=vsen, 101=vtest, 110/111=null |
| [0] | `RW_CSA_OC_EN` | **OC 检测使能** |

#### MISC_IR（`0x4000_7804`，复位 `0x0`）

| 位 | 名称 | 说明 |
|---|---|---|
| [18] | `IR_TJ_OTW_NG`（RO） | 过温预警告实时 Index |
| [17] | `IR_TJ_OTS_NG`（RO） | 过温关断实时 Index |
| [16] | `IR_CSA_OC_NG`（RO） | **CSA 过流实时 Index** |
| [2] | `RO_TJ_OTW_LAT`（RO） | 过温预警告锁存 |
| [1] | `RO_TJ_OTS_LAT`（RO） | 过温关断锁存 |
| [0] | `RO_CSA_OC_LAT`（RO/写1清） | **CSA 过流锁存标志**（软件查询/诊断用；**写 1 可清除**） |

### 4.2 MCPWM 急停（FAIL）模块（MCPWM0 基址 `0x4001_0C00`）

> **重要**：FAIL012 / FAIL345 / CH_DEF / CH_MASK / EIE 等为**写保护寄存器**，
> 写入前需 `MCPWM0_PRT = 0x0000DEAD` 解锁，写后 `MCPWM0_PRT = 0x0000CAFE` 上锁。

#### MCPWM0_FAIL012（`0x4001_0CB0`，写保护，复位 `0x0`）—— 通道 0/1/2 急停

| 位 | 名称 | 说明 |
|---|---|---|
| [15] | `FAIL_0CAP` | FAIL0/1 发生时将 CNT0 值存入 MCPWM0_FCNT |
| [11:10] | `FAIL1_SEL` | 0 = IO MCPWM0_BKIN1；**1 = CSA OC 输出** |
| [9:8] | `FAIL0_SEL` | 0 = IO MCPWM0_BKIN0；**1 = CSA OC 输出** |
| [7] | `HALT_PRT` | HALT 时输出选择：1=正常输出；0=强制保护值 |
| [6] | `MOE` | **1=正常输出；0=输出 CH_DEF 默认值**；EIF.FAIL0/1_IF 任一为 1 → MOE 清 0 |
| [5] | `FAIL1_EN` | FAIL1 输入使能 |
| [4] | `FAIL0_EN` | FAIL0 输入使能 |
| [3] | `FAIL1_POL` | 1=低有效；0=高有效 |
| [2] | `FAIL0_POL` | 1=低有效；0=高有效 |

#### MCPWM0_FAIL345（`0x4001_0CB4`）—— 通道 3/4/5 急停（FAIL2/FAIL3，位定义同上）

#### MCPWM0_CH_DEF（`0x4001_0CB8`，写保护）—— 短路保护通道默认值

| 位 | 名称 | 说明 |
|---|---|---|
| [5:0] | `CH0N/CH0P/CH1N/CH1P/CH2N/CH2P_DEFAULT` | 每通道 1bit 故障默认电平（直接输出到 IO，不受极性控制） |
| [11:6] | `CH3N/CH3P/CH4N/CH4P/CH5N/CH5P_DEFAULT` | 通道 3/4/5 默认值 |

#### MCPWM0_CH_MASK（`0x4001_0CBC`）—— 各通道 FAIL 动作屏蔽

| 位 | 名称 | 说明 |
|---|---|---|
| [0] | `CH0N_FAIL_EN` | FAIL 时 CH0N 是否受控（0=屏蔽，保持原输出；1=强制默认电平） |
| [1] | `CH0P_FAIL_EN` | 同上 |
| [2:5] | CH1N/CH1P/CH2N/CH2P | 同上 |
| [6:11] | CH3~CH5 N/P | 通道 3/4/5 |

> SDK `MCPWM_ch012_init()` 默认把 `CHx*_FAIL_EN` 全部置 DISABLE（屏蔽），
> 需要过流保护时应在工程中显式使能。

#### MCPWM0_EIE（`0x4001_0C90`，写保护）—— FAIL 中断使能

| 位 | 名称 | 说明 |
|---|---|---|
| [7:4] | `FAIL3_IE/FAIL2_IE/FAIL1_IE/FAIL0_IE` | FAIL 中断源使能 |

#### MCPWM0_EIF（`0x4001_0C94`，无写保护，RW1C）—— FAIL 中断标志

| 位 | 名称 | 说明 |
|---|---|---|
| [7:4] | `FAIL3_IF/FAIL2_IF/FAIL1_IF/FAIL0_IF` | **1=发生，写 1 清零** |

> 中断路径（手册 §10）：`MCPWM0_IF0` + `MCPWM0_EIF[5:4]` 置位且使能 → `MCPWM0_IRQ0`。
> 事件枚举见 `mcpwm_type.h`：`MCPWM0_BIT20_FAIL0_IF` ~ `MCPWM0_BIT23_FAIL3_IF`。
> SDK 的 `MCPWM0_IRQHandler`（mcpwm_hal.c）会读 `MCPWM0_IF0`、清 `MCPWM0_EIF` 并回调 `g_mcpwm0_int_callback`。

#### MCPWM0_FLT（`0x4001_0C70`）/ MCPWM0_TCLK（`0x4001_0C7C`）—— FAIL 输入滤波

- `MCPWM0_TCLK.CLK_DIV[1:0]`：第一级分频 1/2/4/8。
- `MCPWM0_FLT.FLT_CLKDIV[7:0]`：第二级分频 1~256。
- 滤波时间：`T = TMCLK × CLK_DIV × (FLT_CLKDIV + 1) × 16`
  （96MHz 下 TMCLK ≈ 10.42ns；FAIL 信号需稳定至少 16 个分频时钟周期才判定有效）

#### MCPWM0_SDCFG（`0x4001_0C74`）—— 故障自动恢复

| 位 | 名称 | 说明 |
|---|---|---|
| [6] | `TR0_AEC` | 1 = 更新事件自动清 `EIF[5:4]` 并**重新置位 MOE**，自动恢复通道 0/1/2 输出 |
| [14] | `TR1_AEC` | 同上，对应通道 3/4/5（EIF[7:6]） |

#### MCPWM0_FCNT（`0x4001_0C54`）—— FAIL 时刻 CNT 快照（诊断用）

## 五、OC 阈值（OC_VTH）来源分析

手册在 MISC_IR / MISC_CSACR1 中多次出现 `OC_VTH`（`CSA > OC_VTH → 过流`），
但**没有任何独立寄存器直接设置 OC_VTH**。结合 MISC_CSACR0 的寄存器布局可判定：

> **OC_VTH 由 CSA 内部 DAC 输出决定**（8 位 `RW_CSA_DAC_OUT[31:24]`，
> 量程 `RW_CSA_DAC_REF[22:20]`），DAC 使能为 `RW_CSA_DAC_EN[11]`。

推算公式（推测，需结合芯片应用手册/FAE 确认分压系数）：

```
V_OC_VTH ≈ RW_CSA_DAC_OUT / 256 × V_DAC_REF
V_DAC_REF = 1.2V / 1.5V / 2V / 2.5V / 3V / VDD33（由 DAC_REF 选择）
```

**示例**：DAC_REF=1.2V、DAC_OUT=0x80(128) → V_OC_VTH ≈ 0.6V；
若采样电阻 10mΩ、增益 ×8、额定相电流 10A → 采样电压 = 10A×10mΩ×8 = 0.8V，
则 DAC_OUT = 0.8V/1.2V×256 ≈ 171(0xAB) 即可把阈值设在 10A 附近。

### 阈值换算建议

1. 先确定**过流保护电流点** `I_OC`（A）。
2. 采样电阻 `Rs`（Ω）、CSA 增益 `G`、偏置 `Vref`（当前 0x1F = VDD33/2）。
3. 比较器输入电压 = `Vref + I_OC × Rs × G`（差模叠加在偏置上，需确认正负方向）。
4. 将比较器输入电压除以 DAC 量程换算为 `DAC_OUT` 8bit 值。

> 注意：OC 比较器比较的**实际是运放输出的电压**（相对偏置的摆幅），
> 正式设计时应以实测波形 + 应用手册的传递函数为准。

## 六、OC_SEL 信号与采样通道对应关系

`RW_CSA_OC_SEL` 中 csp0/1/2 对应 CSA 的 3 路输入对（同相端）：

| OC_SEL 值 | 信号 | 对应输入（同相/反相） | 典型用途 |
|---|---|---|---|
| 000 | `csp0` | GPIO7 / GPIO8（PA7/PA8） | 单相/相电流采样 |
| 001 | `csp1` | GPIO9 / GPIO10（PA9/PA10） | 单相/相电流采样 |
| 010 | `csp2` | GPIO11 / GPIO12（PA11/PA12） | 单相/相电流采样 |
| 011 | `csp1+csp2+csp3` | 三路合成 | 三电阻方案"任一/合成过流"检测 |
| 100 | `vsen` | CSA 运放输出（CSACR0 当前通道） | 对放大后信号检测 |
| 101 | `vtest` | 测试信号 | 出厂测试 |
| 110/111 | `null` | 无 | 不可用 |

> 当前 `CSA_Init()` 把 CSP/CSN 固定为 CH2（GPIO11/12），即**与 `OC_SEL=010(csp2)` 对应**；
> 若要保持固定通道 CH2 采样，OC 检测信号应选 `csp2` 或 `vsen`。

## 七、推荐实现方案

> **✅ 已选定：方案 A（CSA OC 硬件比较器 + MCPWM FAIL 急停）作为本工程实现方案。**
> 理由：响应最快（μs 级）、不依赖 CPU、SDK 中 FAIL 链路已具备（`MCPWM_ch012_init()`
> 默认 `FAIL0/1_Signal_Sel = MCPWM0_FAIL_SEL_CMP(=1)`，即已指向 CSA OC 输出，只需补使能与通道屏蔽）。
> 具体落地步骤见 **第十一章 逐步实现步骤**。

### 方案 A：CSA OC 硬件比较器 + MCPWM FAIL 急停（**选定方案，μs 级硬件保护**）

> 完全由硬件完成保护动作，CPU 只负责初始化与故障处理/恢复。响应最快、最可靠。

**A.1 CSA 侧配置（在 `CSA_Init()` 中追加）**

```c
/* OC 阈值: 内部 DAC 输出 */
CSA->MISC_CSACR0.RW_CSA_DAC_EN   = 1;   /* DAC 使能 */
CSA->MISC_CSACR0.RW_CSA_DAC_REF  = ...; /* 量程, 如 0(1.2V) */
CSA->MISC_CSACR0.RW_CSA_DAC_OUT  = ...; /* 8bit 阈值, 见 §五 */

/* OC 比较器 */
CSA->MISC_CSACR1.RW_CSA_OC_EN    = 1;   /* OC 使能 */
CSA->MISC_CSACR1.RW_CSA_OC_SEL   = CSA_OC_SEL_CSP2; /* 与当前 CH2 对应, 或 vsen */
CSA->MISC_CSACR1.RW_CSA_OC_HYS   = ...; /* 迟滞, 如 010=24mV, 抑制噪声 */
CSA->MISC_CSACR1.RW_CSA_OC_NG_EN = 1;   /* 消抖使能 */
CSA->MISC_CSACR1.RW_CSA_OC_NG    = ...; /* 消抖时长 00~11 (0.5~4us) */
```

**A.2 MCPWM 侧配置（`MCPWM_ch012_init()` 之后追加，注意写保护解锁）**

> 说明：`MCPWM_ch012_init()` 已把 `FAIL0/1_Signal_Sel` 设为 `MCPWM0_FAIL_SEL_CMP(=1)`，
> 即 **FAIL0/1 已默认指向 CSA OC 输出**；但 `FAIL0/1_INPUT_EN`、`CHx*_FAIL_EN`、
> `FAIL0/1_INT_EN` 均默认 DISABLE，需在下方代码中打开。

```c
/* 打开 FAIL 输入与各通道 FAIL 动作 */
MCPWM0_PRT = 0x0000DEAD;                                   /* 解锁写保护 */

/* 1) FAIL0/1 来源 = CSA OC 输出（保险起见再显式确认一次） */
MCPWM0_FAIL012 = (MCPWM0_FAIL012 & ~MCPWM0_FAIL0_SEL_MASK)
               | MCPWM0_FAIL0_SEL_MASK_SET(1);              /* FAIL0_SEL=1 */
MCPWM0_FAIL012 = (MCPWM0_FAIL012 & ~MCPWM0_FAIL1_SEL_MASK)
               | MCPWM0_FAIL1_SEL_MASK_SET(1);              /* FAIL1_SEL=1 */

/* 2) 使能 FAIL 输入，极性高有效（CSA OC 输出：过流=高） */
MCPWM0_FAIL012 |= MCPWM0_FAIL0_EN_MASK_SET(1);              /* FAIL0_EN=1 */
MCPWM0_FAIL012 |= MCPWM0_FAIL1_EN_MASK_SET(1);              /* FAIL1_EN=1 */
MCPWM0_FAIL012 &= ~MCPWM0_FAIL0_POL_MASK;                   /* FAIL0_POL=0 */
MCPWM0_FAIL012 &= ~MCPWM0_FAIL1_POL_MASK;                   /* FAIL1_POL=0 */
MCPWM0_FAIL012 |= MCPWM0_HALT_PRT_MASK;                     /* HALT_PRT=1(调试暂停仍输出) */
MCPWM0_FAIL012 |= BIT15;                                    /* FAIL_0CAP=1: 捕获CNT0到FCNT */

/* 3) 故障默认输出电平（低 6 位: CH0N/CH0P/CH1N/CH1P/CH2N/CH2P_DEFAULT） */
MCPWM0_CH_DEF  = (MCPWM0_CH_DEF & ~MCPWM0_CH_DEF_CH012_MASK)
               | MCPWM0_CH_DEF_CH012_SET(0x00);             /* 示例: 全低=全关断, 按预驱极性定 */

/* 4) 通道 FAIL 动作解除屏蔽: bit[5:0]=CH0N/CH0P/CH1N/CH1P/CH2N/CH2P */
MCPWM0_CH_MASK |= 0x3F;                                     /* CH0/1/2 全部受 FAIL 控制 */

/* 5) 中断使能(可选) */
MCPWM0_EIE |= BIT4 | BIT5;                                  /* FAIL0_IE=1, FAIL1_IE=1 */

/* 6) 清残留标志并恢复 MOE=1(正常输出) */
MCPWM0_EIF = 0x0000003FUL;                                  /* 写1清 FAIL0~3_IF 及 bit[9:4] */
MCPWM0_FAIL012 |= MCPWM0_MOE_MASK_SET(1);                   /* MOE=1 */

MCPWM0_PRT = 0x0000CAFE;                                    /* 上锁写保护 */
```

**A.3 中断处理（挂到 `g_mcpwm0_int_callback`，由 `MCPWM0_IRQHandler` 自动调用）**

> 注意：SDK 的 `MCPWM0_IRQHandler` 在调用回调**之前**已清除 `MCPWM0_EIF`，
> 因此回调内读取 EIF 只能取到 `MCPWM0_IF0` 的 FAIL 位（bit20/21），
> 过流锁存判定请用 `MISC_IR.RO_CSA_OC_LAT`。

```c
#include "mcpwm_hal.h"
#include "CSA_Reg.h"

static volatile uint8_t g_oc_fault_flag = 0;   /* 软件故障锁存 */

static void oc_fail_callback(mcpwm0_int_source_e src)
{
    if (src == MCPWM0_BIT20_FAIL0_IF || src == MCPWM0_BIT21_FAIL1_IF)
    {
        g_oc_fault_flag = 1;                     /* 置故障标志, 主循环处理 */
        /* MCPWM 输出已被硬件强制为 CH_DEF 保护电平, MOE=0 */

        /* 若需读取故障时刻: MCPWM0_FCNT（需在回调外/提前读, 见 §9.8） */
    }
}

/* 故障恢复（由用户按键/上位机/主循环调用） */
static void oc_fault_recover(void)
{
    if (g_oc_fault_flag == 0) return;

    MCPWM0_EIF = BIT4 | BIT5;                    /* 写1清 FAIL0/1_IF */
    MCPWM_CH_DEFAULT(0, false, 0);               /* MOE=1, 恢复通道0/1/2正常输出 */
    g_oc_fault_flag = 0;
}
```

### 方案 B：ADC 采样 + 软件比较（辅助/慢速保护，适合无 MCPWM 的应用）

1. ADC 硬件触发（MCPWM TRIG0 或定时器）周期采样 `CSA_VSEN`（ADC_CH0~2）或 `CSA_VLPF`（ADC_CH3）。
2. 转换结果与软件阈值比较（阈值来自标定值，需扣除偏置与零点）。
3. 超限 → `PWMOutputs(DISABLE)` 或写 `MCPWM0_FAIL012.MOE=0` 关断输出。
4. 优点：阈值可任意调整、可滤波/延时判断、可与电流环共用采样数据。
   缺点：响应受 ADC 采样率与 CPU 处理周期限制（μs~ms 级）。

### 方案 C：ADC 模拟看门狗（AWD）硬件比较（半硬件方案）

- 手册 §19：ADC 每个转换序列可配**模拟看门狗**，监测上下阈值，触发 `AWDIF` 中断。
- 阈值为 12bit 原始 ADC 码，随采样通道独立配置，比较在 ADC 硬件内完成，无需软件换算。
- 触发后仍由软件关断 PWM；比方案 B 快，比方案 A 慢，适合无内部 OC 比较需求的中低速保护。

### 推荐组合

> **本工程选定：方案 A 为主保护（硬件急停）**，方案 B/C 仅作为辅助（软件诊断、
> 故障锁存、阈值标定），不参与快速保护路径。即：
> CSA OC 比较器 + MCPWM FAIL 保证无论软件处于何种状态都能立即关断；
> ADC 采样（可选）用于电流闭环与软件告警。

## 八、恢复 / 解锁机制

| 方式 | 操作 | 适用场景 |
|---|---|---|
| **手动恢复** | 清 `MCPWM0_EIF.FAILx_IF`（写 1）→ 写 `MCPWM0_FAIL012.MOE=1` | 需软件确认故障消除后（如用户按复位） |
| **自动恢复** | `MCPWM0_SDCFG.TR0_AEC=1`（通道 0/1/2）或 `TR1_AEC=1`（通道 3/4/5），下一个更新事件自动清 EIF 并置位 MOE | 可自恢复的瞬时过流 |
| **清除过流锁存** | `MISC_IR.RO_CSA_OC_LAT` **写 1 清除**（虽标 RO，实际 `__IO` 可写） | 解除 CSA 过流锁存，配合中断恢复 |

> 关键机制：**`MISC_IR.RO_CSA_OC_LAT`（bit0）写 1 可清除过流锁存**。
> - 该位在 `CSA_Reg.h` 中声明为 `__IO`（可读可写），并非只读；
> - 若 CSA 过流中断由 OC_LAT 的**上升沿**触发，则清除 LAT 后下一次过流才能再次产生沿触发中断；
> - 若为**电平触发**（LAT=1 持续），中断处理中写 1 清 LAT 可解除中断请求，避免中断风暴。
> - 建议在 `CSA_IRQHandler` 中：读取过流状态 → 处理 → **写 1 清 RO_CSA_OC_LAT**。

> 注意：MOE 被清 0 后，即使 FAIL 信号消失也不会自动恢复（除 TRx_AEC=1 外），
> 这是标准的**锁存型保护**设计，避免故障反复触发导致功率管损坏。

## 九、注意事项与风险提示

### 9.1 引脚复用冲突（当前工程已存在）

- `main.c` 中 UART0_RX 使用 **PTA13**（AF2），TX 使用 PTA14。
- 而 `csa_gpio_init()` 的 mask 包含 `(1<<13)`（PA13），把 PA13 也强制为模拟输入
  （`PA_AFCR` 清复用、`OE=0`、`IE=0`、`ANA=1`）。
- **后果**：UART0 RX 可能失效（引脚被配成模拟，无法接收数据）。
- 建议：CSA 输入实际只用 PA7~PA12（GPIO7~12），`csa_pin_mask` 可去掉 PA13；
  若确实需要 PA13 作为 ADC 模拟输入，请改用其他引脚做 UART。

### 9.2 CSA 过流中断向量未在 SDK 中挂载

- 数据手册中断向量表中 **CSA** 位于向量偏移 `0x9C`（序号 39，IRQ 24 附近），
  但当前 `startup_ARMCM0plus.s` 只展开到 Interrupt0~31（PMU/CodeFlash/UART/SPI/MCPWM/
  I2C/GPIO/TIM13~16/ADC/HALL/QEP/DMA），**没有 CSA 中断向量**；
  `ODS_5010_NVIC.h` 中也未定义 `CSA_IRQn`。
- 若要用"CSA 过流中断"通知 CPU，需**自行扩展启动文件向量表与 NVIC 定义**。
- **替代方案**：推荐走 MCPWM FAIL 中断（`MCPWM0_IRQn`），该中断在当前 SDK 中已完整支持。

### 9.3 MCPWM 写保护

- `MCPWM0_FAIL012/FAIL345/CH_DEF/CH_MASK/EIE/FLT/SDCFG/TCLK` 等均为**写保护寄存器**：
  写入前 `MCPWM0_PRT = 0x0000DEAD`，写后 `MCPWM0_PRT = 0x0000CAFE`，否则写不进去。

### 9.4 时延预算（FAST 保护链响应时间）

| 环节 | 时间 |
|---|---|
| OC 比较器响应 | 亚 μs 级（数据手册未给出具体值，建议实测） |
| OC 指示消抖 `RW_CSA_OC_NG` | 0.5 / 1 / 2 / 4 μs |
| MCPWM FAIL 数字滤波 | `TMCLK×CLK_DIV×(FLT_CLKDIV+1)×16`（96MHz、不分频、FLT_CLKDIV=0 时 ≈ 0.167μs） |
| **合计（推荐配置）** | **约 1~5 μs** |

> 滤波/消抖要**结合功率管短路耐受时间（SCSOA）**折中：太大保护来不及，
> 太小会被 PWM 开关噪声误触发。建议先关消抖/滤波调试，确认无误后再加防抖。

### 9.5 故障输出电平与预驱极性的配合

- `MCPWM0_CH_DEF` 的默认电平**直接输出到 IO，不受极性/通道交换控制**。
- 需按预驱极性（`PRE_DRIVER_POLARITY`）设计"安全电平"：
  例如下管常开短路制动（Low-side 短路）或全关断（三态），务必避免上/下管同时导通。

### 9.6 通道一致性

- `RW_CSA_OC_SEL` 选的信号必须与当前采样通道匹配（固定通道 CH2 → `csp2` 或 `vsen`）。
- 若使用三电阻采样（自动模式 `CSA_AUTO_*_MODE`），注意 `RW_CSA_MODE` 与 `OC_SEL=011` 的组合是否合法。

### 9.7 SDK 默认屏蔽 FAIL 动作

- `MCPWM_ch012_init()`（mcpwm_hal.c）默认把 `CHx*_FAIL_EN` 全部置 **DISABLE**，
  且 `FAIL0/1_INPUT_EN = DISABLE`。仅配置 FAIL012 寄存器不够，
  **还必须**把 `MCPWM0_CH_MASK` 对应位和 `FAIL0_EN/FAIL1_EN` 打开，FAIL 才会真正封锁输出。

### 9.8 中断服务注意

- SDK 的 `MCPWM0_IRQHandler` 会无条件 `MCPWM0_EIF = 0x000003F0UL` 清标志，
  若需在中断里读取 FAIL 原因，应**在清标志前读取 `MCPWM0_EIF`**（或使用回调在清标志前先判断）。
- `RO_CSA_OC_LAT` 虽标 RO，但 **写 1 可清除**（`CSA_Reg.h` 中为 `__IO`）；中断/恢复流程中应写 1 清锁存。

## 十、验证方法建议

1. **寄存器回读**：初始化后回读 `MISC_CSACR1`（OC_EN/SEL/HYS/消抖）、`MISC_CSACR0`（DAC_OUT/REF）、
   `MCPWM0_FAIL012`（SEL/EN/POL/MOE）、`MCPWM0_CH_DEF/CH_MASK`、`MCPWM0_EIE` 确认配置生效。
2. **阈值验证**：逐步增大负载电流，观察 `MISC_IR.IR_CSA_OC_NG` / `MISC_CSACR1.IR_CSA_OC_NG`
   在目标电流点翻转，验证 OC_VTH 换算。
3. **急停验证**：示波器同时观测 PWM 输出（CHxP/CHxN）与采样电阻电压；
   过流瞬间 PWM 应立即切换为 CH_DEF 保护电平，`MCPWM0_EIF.FAIL0_IF=1`，`MOE=0`。
4. **时延测量**：示波器对比"采样电压越过阈值"与"PWM 关断"的时间差，评估保护时延。
5. **恢复验证**：清除 EIF + 置位 MOE 后 PWM 恢复；TRx_AEC=1 时验证自动恢复行为。
6. **软保护验证**（方案 B/C）：ADC 采样值在阈值附近抖动时，确认 AWD/软件判据无误动作。

### 步骤 5：FAIL 链路配置（新增 `MCPWM_OC_FAIL_Init()`）

> 放在 `MCPWM_ch012_init()` 之后调用；因 SDK 已默认 `FAIL0/1_Signal_Sel=CMP(=1)`，
> 核心是打开 FAIL 输入、解除通道屏蔽、设保护电平、开中断。

```c
/*----------------------------------------------------------------------------
 * MCPWM FAIL 急停链路初始化  —— 在 MCPWM_ch012_init() 之后调用
 *----------------------------------------------------------------------------*/
void MCPWM_OC_FAIL_Init(void)
{
    MCPWM0_PRT = 0x0000DEAD;   /* 解锁写保护 */

    /* FAIL0/1 来源确认 = CSA OC 输出 */
    MCPWM0_FAIL012 = (MCPWM0_FAIL012 & ~MCPWM0_FAIL0_SEL_MASK)
                   | MCPWM0_FAIL0_SEL_MASK_SET(1);
    MCPWM0_FAIL012 = (MCPWM0_FAIL012 & ~MCPWM0_FAIL1_SEL_MASK)
                   | MCPWM0_FAIL1_SEL_MASK_SET(1);

    /* 使能 FAIL 输入, 高有效; 捕获 CNT0 到 FCNT */
    MCPWM0_FAIL012 |= MCPWM0_FAIL0_EN_MASK_SET(1);
    MCPWM0_FAIL012 |= MCPWM0_FAIL1_EN_MASK_SET(1);
    MCPWM0_FAIL012 &= ~(MCPWM0_FAIL0_POL_MASK | MCPWM0_FAIL1_POL_MASK);
    MCPWM0_FAIL012 |= MCPWM0_HALT_PRT_MASK | BIT15;

    /* 故障默认电平: 全低=全关断(按预驱极性调整) */
    MCPWM0_CH_DEF = (MCPWM0_CH_DEF & ~MCPWM0_CH_DEF_CH012_MASK)
                  | MCPWM0_CH_DEF_CH012_SET(0x00);

    /* 解除通道屏蔽: CH0N/CH0P/CH1N/CH1P/CH2N/CH2P 全部受 FAIL 控制 */
    MCPWM0_CH_MASK |= 0x3F;

    /* FAIL0/1 中断使能 */
    MCPWM0_EIE |= BIT4 | BIT5;

    /* 清残留标志, MOE=1 正常输出 */
    MCPWM0_EIF = 0x0000003FUL;
    MCPWM0_FAIL012 |= MCPWM0_MOE_MASK_SET(1);

    MCPWM0_PRT = 0x0000CAFE;   /* 上锁写保护 */
}
```

### 步骤 6：故障回调与恢复逻辑

```c
/* isr.c 或 adc_demo_test.c 中实现(见 §7 方案A.3) */

void oc_fail_callback(mcpwm0_int_source_e src)
{
    if (src == MCPWM0_BIT20_FAIL0_IF || src == MCPWM0_BIT21_FAIL1_IF)
    {
        g_oc_fault_flag = 1;     /* 置故障标志(volatile) */
        /* 硬件已封锁 PWM 输出, 此处只做标志/上报/记录 */
    }
}

void oc_fault_recover(void)      /* 用户按键/上位机触发 */
{
    MCPWM0_EIF = BIT4 | BIT5;                    /* 清 FAIL0/1_IF */
    MCPWM_CH_DEFAULT(0, false, 0);               /* MOE=1 恢复输出 */
    g_oc_fault_flag = 0;
}
```

## 十二、硬件功能验证指引（逐步升高 csp2 电压）

> 目标：确认 CSA OC 比较器工作正常 —— 升高 `csp2`（GPIO11，同相端）电压，
> 用**示波器观察 PB4/PB3 IO** 的翻转（替代串口打印）。

### 12.1 当前参数与观察 IO（与代码一致）

| 项 | 值 | 说明 |
|---|---|---|
| `RW_CSA_OC_SEL` | 2（csp2） | 检测 GPIO11(+)/GPIO12(-) 通道 |
| `RW_CSA_DAC_REF` | 0（1.2V） | DAC 量程 |
| `RW_CSA_DAC_OUT` | 171（0xAB） | 8bit 阈值码 |
| **OC_VTH** | **≈ 171/256 × 1.2V ≈ 801mV** | 阈值电压 |
| `RW_CSA_OC_HYS` | 2（24mV） | 迟滞 |
| `RW_CSA_OC_NG` | 1（1μs） | 消抖 |
| 偏置 `RW_CSA_REF` | 0x0B = 1.25V | 运放共模偏置 |
| **PB4 = NG** | 高=过流(实时), 低=正常 | 主循环 2ms 轮询刷新 |
| **PB3 = LAT** | 高=已触发锁存, 低=未锁存 | 主循环 2ms 轮询刷新 |

### 12.2 接线建议

> ⚠ 注意：CSA 运放使能后，输入引脚存在约 1.25V 内部偏置；
> 引脚悬空时可能被偏置拉高，导致初始 NG 状态不确定。验证前请按以下方式接线。

| 引脚 | 接法 |
|---|---|
| GPIO11（csp2 同相） | 接可调电压源输出（建议串 1kΩ 限流，电压源强驱动） |
| GPIO12（csp2 反相） | 接 GND（0V） |
| 示波器 CH1 | 接 **PB4**（NG） |
| 示波器 CH2 | 接 **PB3**（LAT） |

- 电压源量程建议 0 ~ 1.5V，步进 ≤ 50mV；
- 若手头无电压源，可用 10kΩ 电位器在 VDD33 与 GND 之间分压，中端接 GPIO11。

### 12.3 验证步骤

1. **烧录程序**，示波器两通道分别接 PB4/PB3，触发方式选边沿；
2. **GPIO12 接地、GPIO11 置 0V**：应看到 PB4=低、PB3=低（正常）；
3. **逐步升高 GPIO11 电压**（每次 +50mV，停留 1~2 秒）：
   - 预期在 **≈0.78~0.80V** 区间 PB4 由低 → **高**（NG 触发）；
   - 若比较的是 GPIO11 对 GND 绝对电压，翻转点应接近 OC_VTH；
   - 若比较的是差分电压，则应给 GPIO11 与 GPIO12 之间建立压差。
4. **触发后继续升高到 1.2V 再回落**：
   - PB4 在回落到 **OC_VTH − 24mV ≈ 777mV** 以下时应变回低（迟滞）；
   - PB3 一旦变高保持锁存（**写 1 可清除**，见 12.5）。

### 12.4 预期现象表

| GPIO11 电压 | PB4(NG) | PB3(LAT) | 说明 |
|---|---|---|---|
| 0 ~ 0.77V | 低 | 低 | 正常（未到阈值） |
| ≈0.78 ~ 0.80V | **低→高** | 低→**高** | 过流触发点 |
| >0.80V | 高 | 高 | 持续过流 |
| 回落 <0.78V | 高→**低** | 高（锁存保持） | NG 恢复，LAT 仍锁存（**写 1 可清除**） |
| 复位/重新上电 | 低 | 低 | LAT 清 0 |

### 12.5 注意事项

1. **LAT 写 1 可清除**：`MISC_IR.RO_CSA_OC_LAT` 虽标 RO，但 `CSA_Reg.h` 中为 `__IO`，
   **软件写 1 即可清除过流锁存**（无需复位）；中断恢复流程中应写 1 清除。
2. **首次上电若 GPIO11 悬空**：引脚被内部偏置拉至约 1.25V（>0.8V 阈值），可能初始即 NG=1；
   这是正常现象，接线后按 12.3 重新验证。
3. **阈值标定**：若翻转点偏离 801mV，说明 OC 比较器参考点与预期不同（绝对电压/差分），
   可按实测调整 `CSA_DAC_OUT_VALUE` 并重新换算（`VTH(mV) = DAC_OUT × 1200 / 256`）。
4. **IO 为软件轮询刷新（2ms）**：PB4/PB3 反映的是最近 2ms 内的 OC 状态，
   适合慢速升压验证；如需更实时（μs 级）观察需走硬件路径（MCPWM FAIL，步骤 3~6）。
5. **当前未接 MCPWM FAIL 链路**：本步只验证 OC 检测与标志位；FAST 急停（MOE→0）
   需在步骤 3~6（MCPWM FAIL 配置）完成后验证。
6. **限流电阻**：GPIO11 外接电压源时建议串 1kΩ，防止异常灌电流。
7. **观察引脚可改**：PB8(NG)/PB11(LAT) 若被占用，可改 `main.c` 顶部 `OC_NG_IO_*` / `OC_LAT_IO_*`
   宏更换（避开 UART PB9/PB10 与 CSA 模拟输入 PA7~PA13）。

### 12.6 寄存器诊断打印（OC 未触发时使用）

当升高 csp2 电压（如 PA11=2V~2.5V、PA12=GND）而 `IR_CSA_OC_NG` 仍为 0 时，
主循环会每 200ms 打印一行诊断信息（串口 PB9=RX / PB10=TX）：

```
DIAG: C0=0x%08X C1=0x%08X IR=0x%08X | EN=%d SEL=%d HYS=%d DAC=0x%02X NG=%d LAT=%d
```

**正常配置下应看到**：

| 字段 | 期望值 | 含义 |
|---|---|---|
| C0 | `0xAB00_B803` | DAC_OUT=0xAB(bit31:24)、REF=0x0B、DAC_EN、AMP_EN、ANA_EN |
| C1 | `0x000F_0421`（NG=0） | OC_EN、OC_SEL=2、HYS=2、NG_EN、NG=1us、LPF 配置 |
| IR | `0x0000_0000`（NG=0）/ `0x0001_0001`（NG=1 且 LAT 锁存） | NG=bit16、LAT=bit0 |
| EN/SEL/HYS/DAC | 1 / 2 / 2 / 0xAB | 与配置一致 |
| NG | 过流时应为 **1** | 核心判据 |

**按优先级排查**：

1. **C1.bit0(OC_EN)≠1 或 SEL≠2** → `CSA_OC_Init()` 写入未生效，检查调用顺序/编译；
2. **C0.bit31:24≠0xAB 或 bit11(DAC_EN)≠1** → 阈值 DAC 未配置，OC_VTH 异常；
3. **寄存器全对但 NG 恒 0** → 比较器输入/参考问题：
   - 试 `OC_SEL=4(vsen)`（改 `CSA_OC_SEL_VALUE`）；
   - 试抬高/降低输入共模（如 PA12 也抬到 1.25V 附近）；
   - 确认 PA11 引脚实际电压（运放偏置可能拉低高阻源）。
4. **NG=1 但 IO 引脚 0V** → 观察 IO 配置问题（检查 `OC_NG_IO_*` 宏与实际接线）。

### 12.7 CSA 过流中断与 LAT 清除机制（"过流不进中断"排查）

**前提**：向量挂载、NVIC 使能、中断函数均已验证正确（`.map` 确认 `CSA_IRQHandler` 在向量表 index 39）。
若过流时仍不进中断，重点排查**中断触发源**与 **LAT 锁存**：

1. **中断触发源假设**（手册未明确，需实测确认）：
   - 若由 `IR_CSA_OC_NG`（实时）**边沿**触发 → NG 0→1 应触发一次；
   - 若由 `RO_CSA_OC_LAT`（锁存）**上升沿**触发 → LAT 0→1 触发一次；
     **LAT 已锁存时无新沿 → 不再触发**（这是"过流不进中断/只进一次"的常见原因）。
2. **LAT 写 1 清除**：`MISC_IR.RO_CSA_OC_LAT`（bit0）写 1 清除锁存。
   - 中断服务函数中读取后应 **写 1 清 LAT**，解除锁存，使下一次过流能重新触发；
   - 若中断为电平触发（LAT=1 持续），写 1 清 LAT 可同时解除中断请求，避免中断风暴。
3. **建议中断处理流程**（LAT 清除的三种等价写法）：
   ```c
   void CSA_IRQHandler(void)
   {
       g_csa_oc_flag = 1;
       /* 记录: 读 NG 实时 / LAT 锁存 */
       (void)CSA->MISC_CSACR1.IR_CSA_OC_NG;
       (void)CSA->MISC_IR.RO_CSA_OC_LAT;
       /* 关键: 写 1 清除 RO_CSA_OC_LAT(解除中断源/允许下次触发) */
       /* 方式1: 位域(需包含 CSA_Reg.h) */
       CSA->MISC_IR.RO_CSA_OC_LAT = 1;
       /* 方式2: 结构体 Word(仅置 bit0) */
       CSA->MISC_IR.Word = 0x00000001U;
       /* 方式3: 直接寄存器地址写(MISC_IR = 0x4000_7804, bit0) */
       *(volatile uint32_t *)0x40007804UL = 0x00000001UL;
   }
   ```
   > **MISC_IR 寄存器地址**：`CSA_BASE(0x4000_7800) + 偏移 0x04 = 0x4000_7804`。
   > 三种写法效果相同，均为向 bit0（`RO_CSA_OC_LAT`）写 1 清除锁存；
   > **直接地址写**不依赖 `CSA_Reg.h` 结构体，寄存器映射最明确。
4. **验证方法**：
   - 手动 `NVIC_SetPendingIRQ(CSA_IRQn)` 测中断链路是否通（向量/使能）；
   - 过流后读 `RO_CSA_OC_LAT`：若=1 说明已锁存，**写 1 清除后再升压**，观察能否触发中断；
   - 若手动 Pend 能进中断、但过流不触发 → 中断请求信号/触发条件问题（需确认芯片 CSA 中断源）。

> ⚠ 写 `MISC_IR`（0x4000_7804）时只应置 bit0，避免误影响其他位：
> `*(volatile uint32_t *)0x40007804UL = 0x00000001UL;`
> 或位域 `CSA->MISC_IR.RO_CSA_OC_LAT = 1;`（`CSA_Reg.h` 中为 `__IO`，可写）。
