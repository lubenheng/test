## 1.5 测试结果记录与导出

每次有判定结果的测试项都会**边测边写**一条记录到
`Save_Results/measure_Results/测试结果_<芯片>_<时间>.txt`（制表符分隔，程序异常退出也不丢已有数据）。

目录约定：

| 目录 | 内容 |
|---|---|
| `Save_Results/measure_Results/` | 测试项结果：`测试结果_*.txt`、转换后的 `.xlsx`、ADC_IN 测量数据 `.xlsx` |
| `Save_Results/MTP_Table/` | MTP 配置表 `mtp_config_table.txt` 与烧录模板 `*_烧录模板.xlsx` |

记录内容：`时间 | 测试项 | 实测值 | 单位 | Min | Typ | Max | 结果 | 备注`

| 结果 | 含义 |
|---|---|
| `PASS` | 在判定范围内 |
| `FAIL` | 超出范围，或测量失败 |
| `NO-STD` | 校准标准表里该项未填 Min./Max.，无法判定 |
| `MEASURED` | 只测量不判定（IBN 等电流项） |

批量执行结束后终端会提示记录文件路径。菜单里输入 **`e`** 弹出文件选择框（默认打开
`Save_Results`，两个子目录都在其下），按文件内容自动分流：

| 选中的 txt | 处理 |
|---|---|
| `mtp_config_table.txt`（MTP 配置表） | 调用 `other_test/mtp/build_mtp_template.py` 生成烧录模板，输出到同目录的 `<txt名>_烧录模板.xlsx`，可直接给菜单 [32] 用 |
| `测试结果_*.txt`（测试记录） | 转成「明细 + 汇总」工作簿（同名 `.xlsx`） |

测试结果 txt 转换后的表格：

- **测试结果** 工作表：明细，表头冻结 + 筛选，PASS 绿底 / FAIL 红底 / 其它黄底；
- **汇总** 工作表：芯片、记录时间、总条数、各类结果计数、每项的最后一次结果与判定范围。

也可以在命令行直接转：

```bash
# 测试结果 txt → Excel（明细 + 汇总）
python instrument/result_log.py "Save_Results/measure_Results/测试结果_OCD2361_20261021_160000.txt"

# MTP 配置表 txt → 烧录模板 Excel
python other_test/mtp/build_mtp_template.py --from-txt Save_Results/MTP_Table/mtp_config_table.txt
```

## 2. 运行前提

### 2.1 硬件

| 设备 | 说明 |
|---|---|
| IIC 主机 | 串口 `--port`（或 `i2c_config.json` 的 `port`），波特率由 `I2CController` 内部固定 |
| 万用表 | 测电压/电流/电阻，未接则相关测试项返回 `None` |
> **万用表积分配置（Aperture = Time）**：所有电压测量都按**时间**积分，而不是
> NPLC 工频周期数——每次 `CONFigure` 之后都会下发
> `SENSe:VOLTage:DC:APERture:ENABled ON` + `SENSe:VOLTage:DC:APERture <秒>`：
>
> | 路径 | 积分时间 | 常量 |
> |---|---|---|
> | 单次/多次电压测量（`dmm_measure_single_voltage` 等） | **20 ms** | `VOLTAGE_APERTURE_S` |
> | 扫描类快速测量（`dmm_prepare_fast_voltage`，COMP 迟滞用） | **200 µs** | `VOLTAGE_FAST_APERTURE_S` / `COMP_FAST_APERTURE_S` |
>
> 积分时间自动限制在 20 µs ~ 1 s（仪器范围）。原来的 `nplc` 参数保留但已不生效。
> 需要临时改某个测试项的积分时间：`instr.dmm_set_voltage_aperture(0.005)`；
> 回读当前配置：`instr.dmm_get_voltage_aperture()`（返回 enabled / aperture_s / nplc）。

| 示波器 | 测频率（OSC 频率项） |
| 源表 KEITHLEY 2460 | 供电流/电压源，初始化后输出保持关闭 |
| UART（基准板） | CH340，115200；用于 `spi_cmd_set_val mV <V>` 控制 DAC 输出、`cmd_gpio_set_595d_test` 控制继电器 |
| 待测 OCD2361 板 | IIC 从机地址默认 `0x52`，见 [i2c_config.json](../../i2c_config.json) |

### 2.2 启动方式

```bash
cd bench_python_code
python main.py --port COM3
```

- `--port` 是 **IIC 串口号**（如 `COM3`），由 `main.py` 传给 `chip.init_all(instr, port)`；
  不传则回退读 `i2c_config.json` 里的 `port`。
- OCD2361 初始化 **IIC / UART / 万用表 / 示波器 / 源表**，不连接 SWD。
  启动流程见 [main.py:151-167](../../main.py#L151-L167)：
  1. `chip_cfg.init_all(instr, port)` — 建 I2CController、下初始化命令、设速率，
     初始化 UART（CH340/115200）与万用表 / 示波器 / 源表（单项失败可选择忽略继续）；
  2. 发送板级复位命令 `cmd_gpio_set_595d_test reset`，继电器回初始状态；
  3. 进入菜单循环；退出时调用 `chip_cfg.cleanup()` 关闭 IIC，并关闭 UART。

> ⚠️ `main.py` 顶部的 `CHIP` 常量需为 `"OCD2361"`
> （[main.py:21-23](../../main.py#L21-L23)）。

### 2.3 菜单操作

```
[1]  → 进入测试模式使能        [16] → LOCP U相和V相
[2]  → VBG电压                 ...
[0]  → 执行全部测试            [31] → MTP_program
                              [32] → MTP 全片擦除+烧录+校验+自检
                              [33] → IIC 寄存器读写
[q]  → 退出程序
```

- 支持**多选**，用空格分隔：`1 2 3` 依次执行第 1、2、3 项。
- 输入 `0` 执行全部；`0` 优先级最高，与其他键同输时只跑全部。
- 选 `0` 时，名字里含 `TRIM` 或 `修调` 的项会被跳过（本项目暂无此类项）。

## 3. IIC 读写基础

### 3.1 `_get_i2c()` — 取 IIC 控制器

```python
i2c = _get_i2c()
```

返回 `chip.py` 中 `IIC_init_all` 建好的 `I2CController` 单例。
未初始化时抛 `RuntimeError("IIC 未初始化，请确认已执行 IIC_init_all")`。
**每个测试函数第一件事就是调它**，不要在函数里自己 new 控制器。

### 3.2 读写寄存器：`execute_write` / `execute_read`

来自 `instrument.IIC.iic_ops`：

```python
execute_write(i2c, addr=20, index=9, write_data=[0x00, 0x00, 0x00, 0x20])
data = execute_read(i2c, 20, 9)        # 返回 4 字节 list，失败返回 None
```

参数约束（超范围直接抛 `ValueError`）：

| 参数 | 范围 | 说明 |
|---|---|---|
| `addr` | 0 ~ 31 | 5 位，报文中做 bit-reversal 编码 |
| `index` | 0 ~ 63 | 6 位，报文中做 bit-reversal 编码 |
| `write_data` | 必须 4 字节 | 32 位，报文中做 bit-reversal |

报文格式（`iic_ops.build_iic_payload`）：写 `25 + 2字节头 + 4字节数据`；
读 `25 + 2字节头`（STOP）→ `A5`（START）→ 读 4 字节，再做 32 位 bit-reversal 还原。

### 3.3 `_log_read(addr, index)` — 读回并打印

```python
data = _log_read(20, 9)
# 输出: 读回 [20:9] = 00 00 00 20
# 失败: 读回 [20:9] = 无有效返回
```

返回 4 字节 `list` 或 `None`。用于写配置后确认寄存器真的写进去了。

## 4. 校准标准判定（核心）

### 4.1 数据来源

Excel：`test_configs/OCD2361/2361校准标准.xlsx`，工作表 `Sheet1`。
列约定：

| 列 | A | B | C | D | E | F | G |
|---|---|---|---|---|---|---|---|
| 内容 | 测试项 | 测试条件 | Min. | Typ. | Max. | Unit | BIN |

数据从**第 2 行**开始（第 1 行是表头）。

> Excel 的 A 列名字（如 `VBG_Voltage`）必须和测试函数里传给
> `_judge_by_standard` 的字符串**完全一致**，否则会跳过判定并打印警告。

### 4.2 `_load_calib_standard(path, sheet)`

读取整张表 → `{测试项: (Min., Typ., Max., Unit)}`，结果缓存在模块级 `_CALIB_CACHE`，
同一进程内只读一次文件。文件不存在抛 `FileNotFoundError`。

### 4.3 `_to_float(value)`

把单元格转 `float`；转不了（空单元格、`"±5%"` 这类表达式、`"N/A"`）返回 `None`。
**返回 `None` 表示该项该边界不限**，不是 0。

### 4.4 `_judge_by_standard(test_item_name, value, extra_note="")`

```python
_judge_by_standard("VBG_Voltage", mv)                       # → True / False / None
_judge_by_standard("VBG_Voltage", mv, extra_note="修调 12")  # 追加说明到结果行
```

返回值：

| 返回 | 含义 |
|---|---|
| `True` | 在 Min. ~ Max. 内 → 打印 `✅ xxx pass` |
| `False` | 越界 → 打印 `❌ xxx failed` |
| `None` | **无法判定**：`value is None`（测量失败）/ 表里没这个测试项 / Min. Max. 都为空 / 读表异常 |

输出示例：

```
✅ VBG_Voltage pass：判定范围 1180.0000 ~ 1220.0000，Typ 1200.0000，实测 1198.4321
```

#### 单位换算（重点）

表里单位与测量函数返回单位**不一致**，判定前统一换算到测量值单位：

| 表内 Unit | 换算系数 | 说明 |
|---|---|---|
| `V` | ×1000 | 表里 V，万用表返回 **mV** |
| `MV` | ×1 | 已是 mV |
| `MA` | ×1 | 表里 mA，万用表返回 **mA** |
| `UA` | ×0.001 | 表里 µA → mA |
| `A` | ×1000 | 表里 A → mA |
| `HZ` | ×1 | 频率单位 Hz |
| `KHZ` / `MHZ` | ×1000 / ×1e6 | 频率 |
| `Ω` / `OHM` | ×1 | 电阻 |

未识别的单位会打印 `⚠️ 未识别的单位 'xxx'，按 1:1 处理`，此时判定结果不可信，
应到 [tests.py:48-59](tests.py#L48-L59) 的 `_UNIT_SCALE` 里补一条。

## 5. 通用测试流程模板

### 5.1 `_voltage_test(name, addr, index, write_data)`

**写配置 → 回读 → 万用表测电压**，返回电压值（mV，失败为 `None`）。

```python
mv = _voltage_test("VBG电压", addr=20, index=9, write_data=[0x00, 0x00, 0x00, 0x20])
```

内部顺序：
1. `execute_write(i2c, addr, index, write_data)`
2. `_log_read(addr, index)` 打印回读
3. `instr.dmm_measure_single_voltage()` → mV
4. 打印 `电压 = xxx mV`

> `_voltage_test` 在测量成功时会连打两遍电压行（[tests.py:195-196](tests.py#L195-L196)），
> 是历史遗留的重复打印，不影响功能，介意可自行删一行。

### 5.2 `_current_test(name, addr, index, write_data)`

**写配置 → 万用表测电流 → 回读**，返回电流值（mA，失败为 `None`）。
注意它和 `_voltage_test` 的区别：**电流是先测量再回读**。

```python
ma = _current_test("IBN_5U电流", addr=20, index=9, write_data=[0x00, 0x00, 0x03, 0xA0])
```

> HOCP / LOCP（菜单 [15]/[16]/[18]/[19]）已改用源表扫电流找电平翻转点的流程，
> 不再走 `_current_test`，详见 [6.3 电流类](#63-电流类)。

### 5.3 测量仪器接口速查（`instrument.instrument_set as instr`）

| 函数 | 返回 | 单位 |
|---|---|---|
| `instr.dmm_measure_single_voltage()` | float/None | **mV** |
| `instr.dmm_prepare_fast_voltage()` / `dmm_read_fast_voltage()` | bool / float(None) | **mV**（快速通道，单点 3~5 ms） |
| `instr.dmm_measure_single_current()` | float/None | **mA** |
| `instr.dmm_measure_single_resistance()` | float/None | **Ω** |
| `instr.osc_measure_frequency()` | `(freq, period, duty)` | Hz / µs / % |
| `instr.psu_set_voltage(ch, v)` / `psu_get_voltage(ch)` | float/None | V |
| `instr.psu_output_state(ch)` / `psu_output_on(ch)` | bool/None | — |
| `instr.serial_send_and_receive(cmd)` | bytes | — |
| `instr.serial_send_command(cmd, expect=None)` | bool | —（**命令类必用**，见下） |

> **`serial_send_and_receive` 很慢，命令类指令请改用 `serial_send_command`**：
> 前者内部调用 `ser.read(256)`，而 pyserial（Windows）的 `read(size)` 会一直等到
> **收满 size 字节或串口超时**（`serial_init` 默认 `timeout=2`）才返回。
> 固件对 `spi_cmd_set_val` 只回一行 `input pass`（12 字节），所以每条命令都要白等满 **2 s**。
> `serial_send_command()` 只发不读（可选 `expect="input pass"` 在 50 ms 内校验应答），
> 单条约 **1~3 ms**，配合 `_comp_step()` 的 0.1 s 节拍即可让扫描真正跑起来。
> ADC_IN 的逐点 DAC 设置也已改用它。

## 6. 测试项函数一览

### 6.1 使能

| 函数 | 菜单 | 动作 |
|---|---|---|
| `TESTMODE_EN()` | [1] | `[25:0] = 04911555` MTP 上电 → `[25:5] = 5A5A5A5A` MTP Load → 间隔 1s → `[20:15] = 5A5A5A5A` 进入测试模式 → **`[20:0]` bit[24:23]（`RW_TIA_IBIAS_SEL`）= `01`**（`MTPController.open_mtp_en` 也含测试模式这步） |

### 6.2 电压类（`_voltage_test` + `_judge_by_standard`；TIA / UVLO 走专用流程）

除 `VBG_buffer_Voltage` 用 `[19:63]` 外，其余都写 `[20:9]`，靠**写入数据不同**切换内部模拟通道。
`TIA_OUT1/2/3` 需要源表灌 200 mA 并减 VCM，走 `_tia_test()`；`UVLO_Voltage` 需要
DP832A CH1 连续调压 + 示波器判 UO 电平，走专用扫压流程（见下表后的说明）；
`FR_Voltage` / `PWM_IN_Voltage` 分别是「CH2 扫 FR + 万用表看 UO」和
「CH2 扫 PWM + 万用表看 UO」的阈值扫描流程（见 6.5 节）。

> **[2] `VBG_Voltage` 可选择「直接测量」或「TRIM 修调」**：开始前提示 `请确定万用表连接WO，按任意键继续...`，
> 读当前 `VBGTRIM` 后询问测试模式（回车默认 **1 TRIM**）：
>
> | 模式 | 行为 |
> |---|---|
> | **0 直接测量** | 写 `[20:9]` 测一次 WO 电压 → 判定，**不修改 `VBGTRIM`**；返回值即实测电压 |
> | **1 TRIM 修调** | 测一次判定；已达标则不修调；不达标时扫描 `[20:4]` 修调值 0~7，取与 Typ（1250 mV）偏差最小者写回并重新判定 |
>
> 同一套模式选择（`_ask_test_mode`，0=直接测量 / 1=TRIM）也在
> `ADC_VREF_Voltage`、`OSC_P`、`TIA_OUT1/2/3_Voltage` 中使用。
> 修调字段布局：`bit2 → [23:16] bit0`，`bit1:0 → [15:8] bit7:6`（与回读解码严格对应）。
> **判定范围固定为 1235 ~ 1265 mV**（`VBG_LIMITS_MV`，覆盖校准表中该项的 Min./Max.），
> 其它电压项仍按校准表判定。
>
> **修调结果回写 MTP 配置表**：`[20:4]` 的 32 bit 对应 MTP 物理地址 **440**
> （`ADDR=0x1A8, INDEX=4`），`VBGTRIM` 位于 `bit[16:14]`。修调完成后
> `_sync_vbg_trim_to_table()` 会把该 3 位替换为新修调值（其余位不变），
> 写回 `chips/OCD2361/mtp_config_table.py` 并重新生成 `Save_Results/MTP_Table/mtp_config_table.txt`。
> 440 ≥ 416，不参与 CRC，CRC32 不受影响。

> **[14] `ADC_IN_Voltage` 特殊流程（DAC 输出 + ADC 采样）**：
>
> 1. **前置检查**：读 `[20:2]`，必须为 `00 00 00 03`（ADC 时钟 16 MHz，
>    对应 MTP phys **432** 的 `[7:0] = 0x03`）。不满足时打印实际值并中止，
>    可手动确认后强行继续；
> 2. 状态机：`[1:32] = 00 43 FD 22`（选 INT）→ `[1:31] = 00 01 02 00`（启动）；
> 3. ADC 测试使能：`[20:9] = 00 00 03 20`（TEST_ANA = 1100）；
> 4. 选择 4 通道：`[3:1] = 00 00 00 10`；
>    数据右对齐、忽略 adc_error：`[3:0] = 00 00 0D 81`；
> 5. **交互式选择**起始/结束电压与步进（上限固定 **2000 mV**，步进默认 **10 mV**）；
> 6. 每点：UART 下发 `spi_cmd_set_val mV <V>` 设 DAC → 万用表实测 WO →
>    **写 `[3:0] = 00 00 0D C1` 更新 ADC 数据 → 读 `[3:7]` 得 code**
>    （右对齐，取低 14 位）；按 `Vadc = code × ADC_VREF / ADC_FULL_SCALE` 换算
>    （`ADC_FULL_SCALE` 默认 **4096**、VREF 默认 2000 mV，即 1 LSB = 0.4883 mV）；
>    ⚠️ 数据寄存器是 `ADC4_DR<13:0>`（14 bit），若实测 code 在满输入时约为 16384，
>    应把 `ADC_FULL_SCALE` 改为 **16384**（1 LSB = 0.1221 mV）。测试结束会打印
>    「LSB 换算自检：推断满量程 ≈ N」，与配置不符时给出提示，无需靠猜；
> 7. **每一次测量都会留档**：逐点写入结果 txt
>    （测试项 `ADC_IN_<设定>mV`，实测值列 = ADC code，备注含 DAC 测量 / ADC 电压 / 误差）；
>    结束时自动把数据导出为 `Save_Results/measure_Results/ADC_IN_测量数据_<时间>.xlsx`（不再询问），

>
> | 工作表 | 内容 |
> |---|---|
> | `ADC采样数据汇总` | 逐点数据，6 列：`DAC设置值(mV)` / `DAC测量值(mV)` / `ADC code` / `ADC转换电压(mV)` / `误差(mV)` / `LSB` |

>
> **误差 = DAC测量值 − ADC转换电压**（与 ADC 转换方向的偏差），
> `LSB = 误差 / 1 LSB电压`；终端表格、结果 txt、Excel 三处口径一致。

> 4. 粗扫找到翻转区间后，在区间内按 1 mA 步进细扫，取**第一次翻高**的电流为保护点。
> 5. U 相 → 源表 HI 接 UO，V 相 → 源表 HI 接 VO，两相分别记录。
>    每相开始前提示接线，每相结束后源表先回零再关输出。
>
> 结果记录：`HOCP_Current` / `LOCP_Current` / `HOCP_W_Current` / `LOCP_W_Current`
> 各按相记一条（U/V 相共用一项名，相位写在备注里），单位 mA，
> Typ 取理论实测值（200 / 400 mA），备注含 `OCP_CFG` 档位、偏差与 `真实阈值≈3×实测`。
> 校准表未给 Min/Max，故判定列为 `NO-STD`；未找到翻转点记 `FAIL`。
>
> **源表抽/灌电流上限 300 mA**（`OCP_MAX_MA = 300.0`）：四个测试项（HOCP/LOCP 的
> U+V 相、W 相）共用同一上限，粗扫到 300 mA 即停；`_ocp_sweep_scan` 内部还有一道
> 硬保护——任何超过 300 mA 的下发都会抛异常而不是发给源表。
> 默认档（`RW_OCP_CFG = 0` → 0.6 A → 实测 200 mA）留有 100 mA 余量；
> 若把 `RW_OCP_CFG` 改到 `1`（1.2 A → 实测 400 mA），开始扫描前会提示
> 「理论实测值已超过扫描上限」，此时扫到 300 mA 也不会翻转、记 `FAIL`。
>
> 扫描参数都是 `tests.py` 顶部的常量：`OCP_START_MA` / `OCP_MAX_MA` /
> `OCP_COARSE_STEP_MA` / `OCP_FINE_STEP_MA` / `OCP_LOGIC_HIGH_MV` /
> `OCP_SMU_VLIMIT_V`，现场按供电电平与节奏调整 `OCP_LOGIC_HIGH_MV` 即可。
> 抽/灌方向由 `_ocp_protection_test(..., sink=True/False)` 控制。

> **IBN 的万用表档位**：`_current_test` 会先调 `dmm_set_dc_current("100uA")` 把万用表切到
> **直流电流档并锁定量程**（`CONFigure:CURRent:DC` + `RANGe:AUTO OFF`，再回读
> `SENSe:FUNCtion?` / `SENSe:CURRent:DC:RANGe?` 确认）。
> ⚠️ **34465A 的最低电流档是 100 µA**（规格 100 µA ~ 10 A），**没有 1 µA / 10 µA 档**；
> 早前代码里写的 `10uA` 会被仪器以 -222 拒绝，表现就是「万用表没切到电流档、读数仍是电压」。
> µA 级读数用 100 µA 档（6.5 位下分辨力约 0.1 nA），超量程自动换 1 mA 档。
> 档位常量见 `tests.py` 的 `CURRENT_DMM_RANGE` / `CURRENT_DMM_RANGE_BACKUP`。

IBN 仍是 `_current_test`，**只测量、不判定**（没调 `_judge_by_standard`）。若要加判定：

```python
def IBN_5U_Current():
    ma = _current_test("IBN_5U电流", addr=20, index=9, write_data=[0x00, 0x00, 0x03, 0xA0])
    _judge_by_standard("IBN_5U_Current", ma)
    return ma
```

### 6.4 频率 / 温度 / 其他

> **[21] `OSC_P` 测试流程（规范 2.20）**：开始前打印判定范围/目标并提示 `请确定示波器连接UO`（按任意键继续）。
> 询问测试模式（`_ask_test_mode`，回车默认 **0 直接测量**，与该测试的规范用法一致）。
> 写 `[20:9] = 00 00 00 03` 选通 OSC 输出 → 读当前 `RW_OSC_24M_TRIM` →
> **确认示波器连接并只做一次 Auto Scale** → 读当前 `OSC_CHANGE_EN` → **选择测试模式**：
>
> | 模式 | 动作 |
> |---|---|
> | **0 直接测量（默认）** | 把 `OSC_CHANGE_EN`（`[20:3]` **bit[0]**）依次置 **0 / 1**，各测一次频率，分别按 11.620~11.820 kHz 判定并各记一条 `OSC_P`（备注标 `OSC_CHANGE_EN=n`）；结束把 `OSC_CHANGE_EN` **恢复为测试前的值**；返回 `{0: f0, 1: f1}` |
> | **1 TRIM 修调** | 测当前频率 → 判定，通过则结束；不通过时按 **与 `TIA_OUT1` 相同的二分搜索**修调 `RW_OSC_24M_TRIM` |
>
> **TRIM 修调细节**（共用 `_trim_bisect_search`）：
> 1. 先测修调值 `0` 与 `63` 两端，自动判断“code↑ 频率↑ / ↓”的方向；
> 2. 二分收敛到跨过目标 11.72 kHz 的两个 code（6 bit → 约 6~8 次测量）；
> 3. 再补测收敛点两侧的邻近 code，避免平台区/非严格单调时选错；
> 4. 从**所有已测点**（含当前修调值，不重复测量）中取与 11.72 kHz 偏差最小者；
> 5. 写回最优值、再次复测并判定，最后把 `RW_OSC_24M_TRIM` 同步到 MTP 配置表。
>
> 相比原来的“斜率探测 + 估算值 ±5 逐点扫描”，二分法在同样甚至更少的测量次数下
> 能覆盖 0~63 全部范围，不会因斜率估算偏差而漏掉真正的极值点。
> 修调期间若某种 code 写不进/测不到，会跳过该点并继续（已测点仍参与最终比较）；
> 全部点都测不到时写回原修调值并返回 `None`。
>
> 每次测频失败会自动检查示波器会话，失效时重建连接后重试一次
> （避免 `find_resource` 关闭共享 ResourceManager 导致的 `Invalid session handle`）。
>
> 两个寄存器都采用**读-改-写**，不会破坏同寄存器的其它字段：
> `RW_OSC_24M_TRIM` 在 `[20:4]` 的 **bit[13:8]**（与 `VBGTRIM` bit[16:14] 共用）；
> `OSC_CHANGE_EN` 在 `[20:3]` 的 **bit[0]**。
> 相关常量：`OSC_CHANGE_ADDR/INDEX/BIT_LO`、`OSC_MODE_DIRECT` / `OSC_MODE_TRIM`。

> **[23] `COMP0_hy` 迟滞测试流程（规范 2.22）**：
> 开始前打印扫描范围并提示
> `请确定 DAC 输出接 UO、电源 CH2 接 VO、万用表接 WO`。
> 0. **状态机前置**：先写 `[1:32] = 00 43 FD 33`（初始化），再写
>    `[1:31] = 00 01 02 00`（启动），两拍之间间隔 10 ms；
>    与 TIA 测试同样的时序，`[20:9]` 的通道选择必须在这之后写才生效；
> 1. 写 `[20:9] = 00 00 00 07`（TEST_LOGIC=0011）选通 COMP0 测试通道；
> 2. 读当前 `COMP0_HYS`（`[20:0]` **bit[1:0]**），交互选择档位（回车沿用当前）：
>    `00 → ±5 mV`、`01 → ±10 mV`、`10 → ±15 mV`、`11 → ±20 mV`，写入采用读-改-写；
> 3. **电源 CH2 给 VO 加 1 V 固定电压**（测试前未开则打开，结束后恢复为关闭）；
> 4. **升压扫描**（DAC → UO，万用表读 WO）：从**起始电压（默认 950 mV，可设置）**
>    到 **1050 mV** 先按**粗扫步进**（默认 5 mV，可选 1~20 mV）粗扫，
>    WO **> 3000 mV** 判高电平、**< 1000 mV** 判低电平，两者之间算中间态（不判翻转）；
>    找到翻转区间后，先回退到确定的反状态复位，再以 **1 mV 细扫** → 上升沿
>    → **Vhys+ = 上升沿 − 1 V**；
> 5. **降压扫描**：从 **1050 mV** 回到起始电压粗扫，WO 首次 < 1000 mV 后同样
>    1 mV 细扫 → 下降沿 → **Vhys- = 1 V − 下降沿**（负向迟滞，按规范公式取正值）；
>
>    **扫描节拍 = `COMP_STEP_PERIOD_S`（默认 0.1 s/点）**：每点「设 DAC → 读 WO」，
>    测量快于 0.1 s 时补 sleep 到 0.1 s，慢时不再额外等待。
>    为此做了两处提速：① DAC 命令改用 `serial_send_command`（原来
>    `serial_send_and_receive` 每点白等 2 s 串口超时）；② 万用表切**快速模式**
>    （`dmm_prepare_fast_voltage`：一次性配置 DCV/10 V/**Aperture = Time 200 µs**/自动调零 OFF，
>    之后每点只发一条 `READ?`，实测 3~5 ms。普通 `dmm_measure_single_voltage`
>    每点要重新配置并固定等 0.1 s，约 100~200 ms）。
>    测试结束自动 `dmm_finish_fast_voltage()` 恢复默认配置；
>    驱动不支持快速模式时自动退回普通测量，只是慢一些。
>
>    **细扫复位**：粗扫到翻转点后芯片停在翻转后的状态，直接把电压设回
>    「粗扫时读到低电平的那个点」未必能复位（该点可能仍在回差带内）。
>    `_comp_scan_fine()` 会沿远离翻转点的方向按 1 mV 退到读到**确定反状态**为止，
>    再从那里以 1 mV 走到翻转点，保证测到的是真实阈值。
> 6. `finally` 中 DAC 回 0、恢复电源 CH2 原状（本测试打开的才关闭）。
>
> 判定：按所选档位理论值 ±10% 判 Vhys+ 和 Vhys-（档位 00 即校准表的 ±4.5 / ±5 / ±5.5 mV），
> 各记一条 `COMP0_hy`（备注区分 `Vhys+` / `Vhys-`，并含档位与上下沿电压）。
> 起点就已是高电平、或扫到 1050 mV 仍未翻转时给出明确提示（后者记 `FAIL`）。

> 固定电压 `COMP_FIXED_V`、电源通道 `COMP_PSU_CHANNEL`。

## 8. MTP 编程（`MTP_program`，菜单 [31]）

### 8.1 背景

MTP 按**字节**编址，共 **512 字节**（地址 0~511），每 **32 字节**一个扇区，共 16 个扇区。
`MTPController`（`instrument/IIC/mtp_ops.py`）把字节地址映射成 `(ADDR, INDEX)` 寄存器寻址：

```
addr  = byte_addr >> 6      (0 ~ 7)
index = byte_addr & 0x3F    (0 ~ 63)
```

对应关系：「扇区 n」= 字节 `n*32 ~ n*32+31`。

### 8.2 会话流程

```
菜单输入 31
  ↓
打印命令帮助
  ↓
确认进入？(y/N)  → 输入 n 则取消
  ↓
Open MTP EN（写 [25:4] / [20:15] / [30:0] = 5A5A5A5A）
  ↓
MTP> 循环，逐条输入命令
  ↓
输入 q / quit / exit（或 Ctrl+C、Ctrl+Z）退出
  ↓
Close MTP EN（写 [30:0] / [20:15] = A5A500A5，退出后编程/擦除不再生效）
```

> 退出时**不再自动执行 MTP Load**。需要写 `[25:5] = 5A5A5A5A` 时，在 `MTP>` 循环内手工输入 `load`。

返回值：`True` 表示本次会话所有命令都成功，`False` 表示有失败或用户取消。

### 8.2b 全片擦除+烧录+校验（菜单 [32]）

```
菜单输入 32
  ↓
弹出文件选择框（默认打开 Save_Results/MTP_Table），选择模板：.xlsx 烧录模板 或 mtp_config_table.txt（取消则直接返回）
  ↓
解析模板：burn_addrs = 全部 PROGRAM 声明字节（含 >=416）
          CRC32 = crc.py(LSB) 计算「声明字节 ∩ phys < 416」，小端写入 507~510
  ↓
确认？(y/N)
  ↓
Open MTP EN → 全片擦除（ADDR=16 / 0x1000，手册要求固定等待 300 ms）
  ↓
读回全部 512 字节确认空白 0xFF（字节 0~3 为特殊字节，仅打印不计失败）
  ↓
两遍烧录（数据区 + CRC 区 507~510）
  ↓
逐字节回读校验（只打印失败项）
  ↓
finally: Close MTP EN
  ↓
自检（Close 之后）：
  ① MTP Load：[25:5] = 5A5A5A5A，等待 1s
  ② 读 [21:0]，bit2 = 1 → 片上 CRC 校验通过
  ③ 写 [20:15] = 5A5A5A5A 进入测试模式
  ④ 读 [20:4]，与烧录到 MTP phys 440 的同一寄存器值比对 → 读写通过
```

返回值：`True` 表示烧录、逐字节校验与自检全部通过。

模板两种格式，解析口径完全一致（实测同一份配置两路结果相同：352 字节 / 地址 4~455 /
CRC `0x2ACAFA84`）：

| 格式 | 说明 |
|---|---|
| `.xlsx` | 前两行为表头/说明，数据从第 3 行开始，列为 `OPERATION / ADDR / INDEX / [31:24] / [23:16] / [15:8] / [7:0]` |
| `.txt` | [Save_Results/MTP_Table/mtp_config_table.txt](../../Save_Results/MTP_Table/mtp_config_table.txt)，由 `other_test/mtp/build_mtp_config_txt.py` 生成；按行号开头的 `# ADDR INDEX [31:24] [23:16] [15:8] [7:0] PHYS` 数据行解析，其余说明行自动跳过；文件头 `CRC32: 0x...` 仅用于提示（与解析结果不一致会打印 ⚠️，不影响烧录） |

物理地址 `phys = ADDR + INDEX*4`。

自检说明：

- `[21:0]` bit2 由芯片在 MTP Load 后自行比对片上 CRC 与 507~510 的存储值给出，
  为 1 表示 CRC 校验通过。
- `[20:4]` 的 32 bit 在 MTP 中对应 phys **440**，即模板里 `(0x1A8, 4, 0x00, 0x02, 0x59, 0x6A)`
  → 期望回读 `00 02 59 6A`；所选模板未声明 phys 440 时只要求读回有效数据。
- 自检参数都在 [tests.py](tests.py) 的 `MTP_POST_*` 常量里（[tests.py:1764-1773](tests.py#L1764-L1773)）。

### 8.2c IIC 寄存器读写（菜单 [33]）

普通寄存器读写，**独立于 MTP**：不打开/关闭 MTP EN，也不涉及 MTP 字节地址映射，
直接按 `(ADDR, INDEX)` 读写 32 位寄存器。

```
菜单输入 33
  ↓
打印命令帮助
  ↓
IIC> 循环：w 写寄存器 / rd 读寄存器
  ↓
输入 q / quit / exit（或 Ctrl+C、Ctrl+Z）退出
```

| 命令 | 语法 | 说明 |
|---|---|---|
| `w` | `w <ADDR> <INDEX> <B31> <B23> <B15> <B7>` | 写 4 字节并回读比对；数据为 `5A 5A 5A 5A` 时不回读 |
| `rd` | `rd <ADDR> <INDEX> [个数]` | 读 1~N 个连续 INDEX 的 4 字节 |
| `h` / `?` / `help` | — | 显示帮助 |
| `q` / `quit` / `exit` | — | 退出 |

```
IIC> w 20 15 5A 5A 5A 5A
   ✅ 写入 [20:15] = 5A 5A 5A 5A（5A5A5A5A 不回读）
IIC> w 20 9 00 00 00 20
   ✅ 写入 [20:9] = 00 00 00 20（回读一致）
IIC> rd 20 9 3
   ✅      [20: 9] = 00 00 00 20
     [20:10] = 00 00 00 00
     [20:11] = 00 00 00 00
```

> 原先 MTP 命令循环里的 `w` / `rd` 已移到这里，MTP 循环只保留 MTP 相关命令
> （`p` / `r` / `e` / `ec` / `s` / `crc` / `o` / `c` / `load`）。

### 8.3 命令总表

命令行格式：`<命令> <参数...>`，参数用**空格或逗号**分隔（方便从 Excel 直接粘贴）。
**地址是十进制**（可加 `0x` 前缀），**数据是 HEX**。

| 命令 | 语法 | 说明 |
|---|---|---|
| `p` | `p <起始地址> <HEX字节> [HEX字节 ...]` | 编程 1~N 个连续字节，逐字节回读校验 |
| `r` | `r <起始地址> [个数]` | 读 1~512 字节，HEX 输出，每行 16 字节 |
| `e` | `e <扇区 0~15>` | 擦除整个扇区（32 字节），**需输入 y 确认** |
| `ec` | `ec` | 全片擦除 512 字节，**需输入 y 确认** |
| `s` | `s <扇区 0~15> <HEX字节>` | 整扇区 32 字节写同一值（**不先擦除**） |
| `crc` | `crc <起始地址> <结束地址> [期望HEX]` | 读回算 CRC32，给了期望值就比对（**不烧录**） |
| `o` | `o` | 手工下发 Open MTP EN |
| `load` | `load` | MTP Load：固定写 `[25:5] = 5A5A5A5A`（不回读，不带参数） |
| `c` | `c` | 手工下发 Close MTP EN |
| `h` / `?` / `help` | — | 显示帮助 |
| `q` / `quit` / `exit` | — | 退出循环（自动 Close MTP EN） |

编程细节：每个字节写 **2 遍**（`MTP_PROGRAM_PASSES`），字节间延时 **0.01 s**
（`MTP_PROGRAM_BYTE_DELAY`），写完立即回读比对，不一致则报 `校验不一致`。

### 8.4 典型使用示例

**① 烧录一小段数据到地址 100 起**

```
MTP> p 100 5A 00 FF
     ✅ 地址 100 = 0x5A
     ✅ 地址 101 = 0x00
     ✅ 地址 102 = 0xFF
   ✅ 地址 100~102 共 3 字节编程完成
```

字节超过 8 个时改为每 8 个打印一次进度：

```
MTP> p 0 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F 10
     编程进度 8/16，失败 0 项
     编程进度 16/16，失败 0 项
   ✅ 地址 0~15 共 16 字节编程完成
```

**② 回读校验**

```
MTP> r 100 4
     100: 5A 00 FF 00
   ✅ 读取地址 100~103 共 4 字节完成
```

单个地址：

```
MTP> r 100
     地址 100 = 0x5A
```

回读失败的地址在批量输出里显示为 `--`。

**③ 改数据前先擦除扇区**

地址 100 属于扇区 3（96~127）：

```
MTP> e 3
     扇区 3 = 字节 96~127，其内已烧录数据将被清除
     确认擦除？(y/N): y
   ✅ 已下发扇区 3 擦除指令
```

**④ 整扇区填值（不擦除，直接把该扇区全写成一个字节）**

```
MTP> s 3 FF
     扇区 3 = 字节 96~127，统一写入 0xFF
     填值进度 8/32，失败 0 项
     ...
   ✅ 扇区 3 共 32 字节全部写入 0xFF 并校验通过
```

**⑤ 全片擦除**

```
MTP> ec
     确认全片擦除 MTP（清空全部 512 字节）？(y/N): y
   ✅ 已下发 MTP 全片擦除指令（ADDR=16 / 0x1000，已等待 300 ms）
```

**⑥ CRC32 校验**

只算不比对（地址 4~506）：

```
MTP> crc 4 506
   ✅ CRC32(地址 4~506，503 字节) = 0x0F348CFA
```

与期望值比对：

```
MTP> crc 4 506 0F348CFA
   ✅ CRC32(地址 4~506) = 0x0F348CFA，与期望值一致
```

不一致时：

```
   ❌ CRC32(地址 4~506) = 0x12345678，与期望值 0x0F348CFA 不一致
```

**⑦ 手动开关 MTP EN**

```
MTP> c        # Close MTP EN，之后编程/擦除不生效
MTP> o        # Open MTP EN，恢复
```

**⑧ MTP Load**

固定写 `[25:5] = 5A 5A 5A 5A`（`ADDR=25`, `INDEX=5`），写完立即回读校验：

```
MTP> load
   ✅ MTP Load 完成：[25:5] = 5A 5A 5A 5A（回读一致）
```

### 8.5 安全注意事项

1. **MTP 只能把 bit 由 1 写成 0**。编程前目标字节必须已擦除（空白 = 0xFF）。
   直接对已写过数据的字节再 `p`，只能把 1 变 0，回读会出现 `校验不一致`。
   此时先 `e <扇区>` 擦除再重写。
2. **扇区擦除会清掉该扇区全部 32 字节**（含其中已烧录的数据），所以 `e` 和 `ec` 都强制要 `y` 确认。
3. `s`（整扇区填值）**不会自动先擦除**，同样受第 1 条限制。
4. 退出循环时无论成败都会执行 `Close MTP EN`；**若程序被强杀（任务管理器）则不会执行**，
   下次连接后建议先 `c` 一次再操作。
5. 编程/擦除命令只下发指令，**不等待芯片内部完成**，靠回读校验来确认结果。
   若批量烧录失败率高，可调大 `MTP_PROGRAM_BYTE_DELAY`、`MTP_PROGRAM_PASSES`。

## 9. 常见问题排查

| 现象 | 原因 / 处理 |
|---|---|
| `RuntimeError: IIC 未初始化` | 没走 `IIC_init_all` 分支，或 `main.py` 的 `CHIP` 不是 `"OCD2361"` |
| `⚠️ 校准标准中未找到测试项 'XXX'` | Excel A 列名字与代码里的字符串不一致（大小写、下划线、空格） |
| `⚠️ 无判定标准（表中 Min./Max. 均未填）` | Excel 的 C/D/E 列没填，只有 Typ. 时无法判定 |
| `❌ xxx failed：测量失败（无有效读数）` | 万用表没接/没初始化，或量程不合适 |
| 判定结果明显不对 | 检查 Excel 的 Unit 列是否在 `_UNIT_SCALE` 里；不认识的单位会按 1:1 处理并告警 |
| `读回 [20:9] = 无有效返回` | IIC 通信异常：检查 `--port`、波特率、板卡供电、从机地址 |
| `ADDR 必须在 0~31 之间` | 写寄存器时 addr 越界，查手册确认地址 |
| `写入数据必须为4字节` | `write_data` 必须正好 4 个字节，如 `[0x00,0x00,0x00,0x20]` |
| MTP 编程报 `校验不一致` | 目标字节没擦除（只能 1→0），先 `e <扇区>` |
| `模块加载失败 (OCD2361)` | `chips/OCD2361/` 下缺少 `chip.py` 或 `tests.py` |
| 中文乱码 | `main.py` 已 `chcp 65001`；手工跑脚本时需自行设置控制台编码 |
| `Invalid session handle. The resource might be closed.` | **pyvisa 的 ResourceManager 是「每个 VISA 库一个实例」的单例**（`ResourceManager.__new__` 复用 `visa_library.resource_manager`），`rm.close()` 会把本进程内所有仪器已打开的会话一起关掉。已从 `visa_backend.find_resource` 与万用表/示波器/源表/电源/信号源的关闭路径去掉 `rm.close()`；万用表切档与读数前会 `*IDN?` 探活，失效时自动重连一次 |
| `错误：万用表不支持电流量程 10uA` | 34465A 最低电流档是 **100 µA**（规格 100 µA~10 A），没有 1 µA / 10 µA 档，请用 `100uA` / `1mA` 等 |
