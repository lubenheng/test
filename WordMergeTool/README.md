# Word 文档按章节合并工具

一个小巧的图形化工具：把多份 Word 文档按章节合并成一本，并自动生成目录。

## 启动

双击 **`启动合并工具.bat`**。

也可以直接运行：

```bat
pythonw word_merge.pyw
```

## 使用步骤

1. 点击「添加文件…」选择文档，或「添加文件夹…」批量添加，也可以直接把文件/文件夹拖进窗口。
2. 列表中的每一行代表一章，显示识别到的章号、文件名和标题。
   - 勾选「按章号自动排序」时，仅按各文档的章号依次排列；章号相同的文档保持原有顺序。
     排序只调整文档顺序，不会改动文档里的标题编号或多级列表编号；
   - 也可以用「上移 / 下移」手动调整顺序（手动调整后自动排序会关闭）。
3. 需要补入或替换单独一章时，点击「合并/导入单章节…」：
   1. **先选择单个章节文档**；
   2. **再选择要合并到的总文档**，程序会列出总文档的章节并查找同章节
      （先按章号匹配，章号相同时或标题文字相同即视为同一章）；
   3. 总文档中已有同章节时，默认选中「替换」：
      - **替换**：用本章替换总文档中的该章节，只替换这一章的内容，
        总文档其余章节的内容和格式保持不变；
      - **插入**：按章号插入到总文档的对应位置，原有章节保持不变；
      没有同章节时只能插入，按章号确定位置，找不到位置时追加到文末；
   4. 选择保存位置（默认是 `总文档名_更新.docx`）后执行，总文档本身不会被修改。
4. 按需勾选：
   - **每章另起一页**：各章之间插入分页符（默认开启）；
   - **自动生成目录**：在正文前插入目录（默认开启），目录标题可修改；
   - 合并默认**只按章节拼接**：不修改任何章节文档（源文件只读），也不导入或删除样式；
     合并时以列表中的**第一个文档为主文档**（与「合并到文档」一致），
     它的样式库、标题多级列表编号、页眉页脚、页面设置原样保留，后续章节依次插入，
     字体、段落格式、图片、表格都原样保留。
     与主文档样式相同的章节直接沿用主文档的样式和编号列表，标题编号按顺序连续；
     同名但定义不同的样式会随所在章节各带一份副本，不会互相覆盖；
   - **样式模板**：界面中选择的模板默认**不参与合并**，仅供「单独处理样式」
     「套用模板样式」「生成汇总模板」使用；只有显式勾选下面的样式选项，合并时才会用到模板；
   - **删除模板之外的样式**（默认关闭）：导入模板后，删除文档中与模板无关的样式。
     删除后，原本使用这些样式的段落会回落到默认的「正文」样式，直接格式保留。
     未选择模板时，该选项表示仅删除正文中未使用的自定义样式。
     两种情况下都会同时清理**同名重复的未使用样式**（合并多份文档后常出现两个「正文」），
     保留正文实际引用的那一个。
   - **合并前先逐个文件统一为模板样式**（选择模板后可用，默认关闭）：
     1. 先用 Word 逐个打开每份源文件，把模板样式导入该文件（等同「管理样式 → 导入/导出」），
        并删除该文件中与模板无关的样式，保证所有文件的格式统一；
     2. 默认只处理临时副本，源文件保持原样；只有再勾选「写回源文件」时才会直接修改源文件，
        修改前自动备份到第一个源文件所在目录的 `_样式统一备份_日期_时间` 文件夹；
     3. 然后再按章号顺序用 `docxcompose` 合并内容，合并阶段不再改动任何格式
        （`.doc` / `.rtf` / `.docm` 会先另存为临时 `.docx` 再合并）。
     勾选后合并结果中的目录是域，首次打开时 Word 会提示更新域，选择「是」即可。
   - **写回源文件**（默认关闭）：勾选后，「合并前统一为模板样式」和「单独处理样式」
     会把结果直接写回源文件（处理前自动备份）；不勾选时源文件只读，
     合并使用临时副本，单独处理的结果输出到新文件夹。
5. 确认输出路径（默认是第一个文档所在目录下的 `合并结果.docx`）。
6. 点击「开始合并」，完成后可直接打开文档。

### 单独处理样式（不合并）

「单独处理样式」区域可以不合并、只整理样式，适合在正式合并前统一一批文件：

1. 在「样式模板」处选择模板（导入时才需要）；
2. 勾选要执行的动作：
   - **导入样式模板**：把模板中的全部样式导入每个文件；
   - **删除多余样式**：选了模板时删除模板之外的样式；未选模板时只删除正文中未使用的样式；
     同时清理同名重复且未被正文使用的样式（保留实际引用的那一个）；
3. 在列表中选中文件（按住 Ctrl / Shift 多选），未选中时处理列表中的全部文件；
4. 点击「处理选中文件…」，确认后执行。

导入样式模板时，如果模板的标题样式自带多级列表，而标题文字里已经手写了编号
（如「第1章 概述」「1.1 特性」），程序会取消这些标题从样式继承的自动编号
（在段落上写入「无编号」），避免出现「1 第1章 概述」这样的重复编号；
样式定义本身不变，标题文字保持原样。文字里没有编号的标题照常使用模板的自动编号。

默认不修改源文件：处理结果输出到第一个源文件所在目录新建的
`样式处理结果_日期_时间` 文件夹。勾选「写回源文件」后才会直接修改源文件，
处理前自动备份到 `_样式统一备份_日期_时间` 文件夹，完成后提示是否打开备份文件夹。

### 删除标记区间（不合并）

用一对标记圈出文档中临时写的内容，处理时整段删掉，适合清理草稿、内部批注或
「待定稿后删除」的段落：

1. 在「删除标记区间」区域确认起止标记，默认是 `*ocs_start*` 与 `*ocs_end*`
   （标记写不写两侧的星号都认，`ocs_start` 同样能匹配 `*ocs_start*`）；
2. 在列表中选中文件（按住 Ctrl / Shift 多选），未选中时处理列表中的全部文件；
3. 点击「删除选中文件中的标记区间…」，确认后执行。

删除规则：

- 两个标记本身、以及它们之间的全部内容（段落、表格、图片、页眉页脚以外的一切正文元素）一并删除；
- **只删内容，不改格式**：其余段落的样式、字体、缩进、编号、分页设置都保持原样；
- 删除后清理切口两侧遗留的空格与空段落（含原本就紧挨着标记的空段落），
  不会留下多出来的空行，也不会动其他位置的空段落；
- 一对文档里可以有多处标记，按出现顺序依次配对删除；标记写在同一个段落里时，
  删除后左右文字自动接上；
- 两个标记之间跨表格、跨单元格会导致无法安全删除，这类文件会跳过并在完成提示里列出；
- 标记本身不在同一段落（中间被回车断开）时无法识别，请写在同一行。

处理结果默认输出到第一个源文件所在目录新建的 `标记删除结果_日期_时间` 文件夹，
源文件不动；勾选「写回源文件」后才会修改原文件并备份到 `_标记删除备份_日期_时间`。

### 合并 / 替换到已有文档

「合并到文档…」用于把列表中的章节并入一本已经存在的书稿，而不是生成新书：

1. 在列表中选中要处理的章节（未选中时使用列表中的全部文件）；
2. 点击「合并到文档…」，选择目标文档（`.docx` / `.doc` / `.docm` / `.rtf`）；
3. 在弹窗中选择方式：
   - **合并**：按章号把章节插入目标文档的对应位置，原有内容保持不变；
   - **替换**：按章号替换目标文档中的同名章节；目标文档里找不到该章号时，自动按章号插入；
4. 选择保存位置（默认是 `目标文件名_更新.docx`），确定后执行。

说明：

- 目标文档按「标题 1」切分章节（没有一级标题时改用其他级别的标题），并用标题或文件名中的章号匹配；
  标题文字里没有章号时，改用标题上的多级列表编号作为章号；
- 章节文档的内容按原样插入（不删空段落、不做任何整理），因此章节文件应以该章标题开头；
- 只插入章节内容：不导入模板样式，也不改写目标文档已有的样式定义；
  与目标文档同名但定义不同的样式会随该章节另存一份副本，章节原有格式原样保留；
- 导入章节的标题会沿用目标文档的编号列表，因此替换后后续章节的编号不会前移
  （如附录仍是第 3 章），插入新章节时后续章节会自动顺延；
- 合并结果总是另存为新文件，目标文档和章节文档本身都不会被修改
  （输出路径与目标/章节文件相同时会提示改选）；
- 合并模式下会遵循「每章另起一页」选项；替换模式保持目标文档原有版式，不额外插入分页符；
- 结果文档原有的目录会由 Word 自动更新页码；章节编号沿用各文档原有的多级列表编号。

「合并/导入单章节…」用于只处理一章的情况：先选章节文档、再选总文档，
总文档中已有同章节时可选择替换该章节，效果与上面的「替换」方式相同。

### 按章节拆分总文档

「拆分总文档…」用于把一本已经合并好的书稿重新拆成每章一个文件：

1. 点击「拆分总文档…」，选择要拆分的总文档（`.docx` / `.doc` / `.docm` / `.rtf`）；
2. 确认识别到的章节列表，然后选择保存文件夹；
3. 程序按章节标题（优先「标题 1」，没有一级标题时改用其他级别的标题）切分文档。

说明：

- 每个拆分文档都是原文档的完整副本，只删除其他章节的内容，
  样式、主题、多级列表编号、页眉页脚、图片、表格、页面设置等格式全部原样保留，不套用任何格式；
- **章节标题的编号保持原样**：拆分时会先算出每个标题在总文档中的编号，再把起始编号写回
  拆分文档，因此第 2 章拆出的文件仍是 2、2.1、2.2，不会重新从 1 开始编号；
  正文中的编号列表同样保持原有编号（如总文档里的 5.、6. 在拆分后仍为 5.、6.）；
  标题编号若是手写文字（如「第2章 概述」）则原样保留；
- 文件名为「章号_章节标题_日期.docx」，日期为拆分当天（如 `2_系统时钟_20261028.docx`）；
  标题开头的「第2章」「1.2」「Chapter 2」等编号会自动去掉，未识别到章号时使用章节顺序号；
  文件名中的非法字符会替换为下划线，重名时自动追加 `_2`、`_3`；
- 只输出各章正文：第一张章节标题之前的内容（封面、目录等）不会进入任何拆分文档；
- 章节末尾仅含分页符的空段落会自动去掉，避免每个文件末尾多出一页空白；
- `.doc` / `.rtf` 需要安装 Microsoft Word 才能读取。

### 生成样式参考汇总模板

「生成汇总模板…」以一份参考文档（用户手册模板或样式库模板）为样板，生成一份
**样式参考汇总模板**，里面列出每种样式的中文格式说明和对应示例：

1. 在「样式模板」处选择参考文档（`.docx` / `.dotm` / `.dotx` 均可）；
   未选择时会弹窗让你指定；
2. 点击「生成汇总模板…」，选择保存位置；
3. 生成结果按三组排列：
   - **一、标题样式**：标题 1、标题 2 …（示例直接带多级列表编号）；
   - **二、正文与段落样式**：段落正文、单段落、注意事项等；
   - **三、表格与图注样式**：图注、表字体，并附一个示例表格。

每个样式上一行是灰色小字说明（如「中文字体-宋体，西文字体-Times New Roman，字号-小四（12 磅），首行缩进 2 字符，1.5 倍行距」），
下一行是按该样式排版的示例文字。示例文字优先取自参考文档中该样式的实际内容。

汇总模板沿用参考文档的页面设置（纸张、页边距、页眉页脚）；参考文档中实际用到的样式才会收录，
避免把 Word 自动生成的“样式 标题 1 + …”“列出段落3”等无关样式堆进汇总模板。

### 分析并套用模板样式

「套用模板样式…」用于检查单个章节文档或已合并的整本文档，并按模板统一格式：

1. 先在「样式模板」处选择模板；
2. 点击「套用模板样式…」，选择要分析的文档（单章或合并后的整本）；
3. 文档包含多个章节时，可先选择处理范围：整个文档，或其中某一章；
4. 弹窗**逐个列出文档中实际用到的样式**（不再按级别归并）：
   当前样式、对应段落数、位置（正文 / 表格 / 正文+表格）、自动识别的级别、当前字体/字号、
   是否带多级列表，以及模板中自动匹配的样式；
   文档中的表格会单独识别并在弹窗顶部列出数量和表格样式（行列数）；
5. 每个样式都可以单独勾选/取消，并在右侧下拉框改选模板中的**任意段落样式**
   （下拉项会显示该样式的字体、字号、是否加粗），例如把「正文」换成模板里的「段落正文」，
   或把某一级标题换成模板的其他样式；下拉第一项「（保留原样式）」表示不改这个样式；
6. 选择保存位置后执行，结果另存为新文件。

说明：

- 处理整个文档时，修改的是文档中每个样式本身的字符与段落定义（字体、字号、加粗、缩进、行距、对齐等），全篇统一；
  模板样式的继承链（basedOn）会连同上级样式一起取用；
- 处理某一章时，样式定义是整篇共享的，因此改为给这一章的文字直接设置格式，不影响其他章节；
- 默认勾选「清除文字的直接字符格式」和「清除直接段落格式」，去掉各段文字上的手动字体、字号、加粗、颜色，
  以及段落上的手动缩进、行距、对齐，否则这些直接格式会盖过模板样式，出现“正文实际样式与模板不符”；
- 目标样式若继承自其他样式（basedOn），套用后会把模板没有声明、但仍会从上级继承到的格式
  （如首行缩进、行距、加粗）显式写回默认值，避免“改正文导致标题也带首行缩进”一类问题；
- 套用完成后会**自动校验**所选样式的实际生效格式与模板样式是否一致，
  不一致的样式会写入日志并在完成提示中列出；
- 目录段落会自动跳过；**表格只更新文字格式**：表格样式、边框、底纹、列宽、合并单元格、
  单元格对齐与缩进等设置全部保持不变；表格文字使用的样式同样可以在弹窗里选择模板样式
  （表格文字样式名含「表格 / 表字体」时，会自动推荐模板中的「表字体」这类样式）；
- 勾选「表格只更新文字格式…」（默认开启）时，只用于表格文字的样式只改字符格式、不改段落格式；
  同一样式既用于正文又用于表格时，样式本身的段落格式会随正文更新，表格边框等设置仍不变；
- **已有的大纲级别和多级列表编号保持不变**；标题样式缺少多级列表（或编号定义已丢失）时，
  会从模板导入多级列表定义并补到标题样式上，编号按 1、1.1、1.1.1 连续显示；
  文字中已经手写编号（如「第2章」「1.2」）的标题会自动跳过，避免编号重复；
- 只有标题类模板样式才会自动补多级列表，正文类样式不会因此变成项目符号列表。

## 章号识别规则

按以下顺序识别每份文档的章号：

1. 文档第一个一级标题（没有一级标题时取第一个标题），例如 `第3章 系统时钟`、`1.2 特性`、`Chapter 4`；
2. 标题里没有章号时，尝试从文件名识别，例如 `第03章_附录.docx`、`1.2-时钟.docx`、`03_测试.docx`。

识别不到章号的文件会标记为「未编号」，按添加顺序排在已编号章节之后，可手动调整。

## 合并效果

- 默认用 **docxcompose** 按章号顺序拼接文档内容（`.doc` / `.rtf` / `.docm` 先用 Word 转成临时 `.docx`）；
- **仅按章节合并**：不修改任何章节文档（源文件只读），不导入模板样式、不删除样式，
  各章的字体、段落格式、样式库、图片、表格原样保留；
- 合并时**以第一个文档为主文档**（与「合并到文档」相同）：
  主文档的样式库、标题多级列表、页眉页脚、页面设置原样保留，后续章节依次插入，
  不会再套用空白文档的默认样式，标题样式仍是「标题 1 / 标题 2 …」，
  多级列表编号和目录都能正常显示；
  与主文档样式相同的章节沿用主文档的编号列表，标题编号按顺序连续（第 1 章、第 2 章…）；
  同名但定义不同的样式会随章节各带一份副本（如「正文_1」），并用该章节自己的编号起始值，
  不会用某一章的样式覆盖其他章；
- 样式模板、删除模板之外的样式、合并前统一为模板样式都改为**手动勾选**（默认关闭），
  只有勾选后才会对样式做处理；「写回源文件」默认关闭，样式处理结果默认只写入临时副本；
- 自动在文首生成目录（Word 域），并用 Word 更新页码；没有 Word 时打开文档后按 F9 更新；
  目录标题不会出现在目录里，正文第一段自动另起一页；
- 各文件页码保持连续编号；
- docxcompose 合并失败时自动回退到 Microsoft Word 的 InsertFile 合并方式，
  回退方式同样以第一个文档为主文档（Word 对同名样式的映射可能带来细微差异）。

## 打包为独立 exe

双击 **`打包exe.bat`**（实际调用同目录的 `build_exe.bat`）即可打包，
脚本结束后会自动运行一次自检，结果写到 `dist\selftest.log`。

默认生成**单文件**程序：

- `dist\WordMergeTool.exe`（约 31 MB）—— 单独一个文件，复制走即可，
  首次启动需要解压到临时目录，启动约 10 秒；

需要更快启动时可打包**文件夹版**：

```bat
build_exe.bat onedir
```

生成 `dist\WordMergeTool\`（约 79 MB），启动约 2~3 秒，分发时整个文件夹一起复制。
两种产物可以并存。

两种方式都无需目标电脑安装 Python，但仍需安装 Microsoft Word 才能处理
`.doc` / 目录页码等依赖 Word 的功能。

打包命令的核心参数：

```bat
python -m PyInstaller --noconfirm --clean --onefile --windowed ^
    --name WordMergeTool --collect-all tkinterdnd2 ^
    --hidden-import win32com --hidden-import win32com.client ^
    --hidden-import pythoncom --hidden-import pywintypes ^
    --hidden-import docxcompose --hidden-import docx ^
    word_merge.pyw
```

说明：

- `--collect-all tkinterdnd2` 用于带上拖拽所需的 tkdnd 动态库，缺少该参数时拖拽功能会静默失效；
- `--windowed` 不显示黑色控制台窗口；
- 单文件 exe 每次启动都要解压到临时目录，启动较慢属正常现象；
- 打包产物可在任意目录运行，不需要随附 `.pyw` 或模板文件（模板在界面里选择）。

### 打包后自检

```bat
WordMergeTool.exe --selftest
```

会在 exe 同目录写 `selftest.log`，逐项检查 tkinter、python-docx、lxml、docxcompose、
pywin32、tkinterdnd2 以及 docx 读写是否正常，用于排查“换了台电脑打不开/功能缺失”的问题。

## 依赖

需要 Python 3.10+，以及：

```bat
pip install python-docx docxcompose pywin32 tkinterdnd2
```

其中：
- `pywin32` 用于调用 Microsoft Word（负责旧格式转换、样式导入、目录页码更新）；
- `docxcompose` 用于按章节拼接文档内容；
- `tkinterdnd2` 用于拖拽文件（缺少时仍可用按钮添加）。

## 说明与限制

- 目录能否生成取决于源文档是否使用 Word 内置的“标题 1/2/3”样式；自定义标题样式不会出现在目录中。
- 默认合并不碰样式：不会导入模板样式，也不会删除或覆盖任何章节的样式。
  只有手动勾选「删除模板之外的样式」等样式选项时，模板样式才会覆盖同名样式、
  模板之外的样式才会被删除（相关段落回落到「正文」样式）。
  Word 内置样式不会被删除（Word 也不允许删除），其中未被使用的内置样式可在「管理样式」中隐藏。
- 「合并前先逐个文件统一为模板样式」和「单独处理样式」默认只处理临时副本，源文件保持原样；
  只有勾选「写回源文件」时才会直接修改源文件，并自动备份到 `_样式统一备份_*`，请确认备份后再删除。
  统一为模板样式的操作需要安装 Microsoft Word；无 Word 时只处理 `.docx` 文件。
  「删除标记区间」同样默认输出到新文件夹，写回源文件时备份到 `_标记删除备份_*`。
- 合并结果中同名但定义不同的章节样式会各带一份副本（如「正文_1」），这是保留各章原格式的代价；
  如需统一为一套样式，可合并后再用「套用模板样式…」处理整本文档。
- 各源文档的页眉页脚不会被完整保留，建议合并后在输出文档中统一设置页眉页脚。
- 合并过程中请勿用 Word 打开输出文件，否则保存会失败。
- 「删除标记区间」只按文字匹配标记：标记被回车拆到两个段落时无法识别；
  两个标记分处不同表格单元格时无法安全删除，该文件会被跳过并在完成提示中列出。
- `.doc` 旧格式可以合并，但只有安装了 Word 才支持；`.docx` 无 Word 时也可回退合并。
- 合并前建议先备份原始文档。
